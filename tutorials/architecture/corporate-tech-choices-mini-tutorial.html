Kontekst korporacyjny

Aplikacja „korporacyjna” to zwykle: compliance, audyt, SSO, SLA, zespół 5–50 devów, systemy legacy obok, budżet na utrzymanie 5–10 lat. Technologia musi być znana rekrutacji, wspierana przez vendora/społeczność i zgodna z polityką bezpieczeństwa.

Dobry wybór ≠ najnowszy hype. Dobry wybór = najmniej niespodzianek przy skali organizacji + droga migracji.

Trend 2025–2026: „modular monolith first”

Po fazie „microservices everywhere” firmy wracają do monolitu modułowego + wycinek serwisów tam, gdzie boli. Mniej operacyjnego overheadu niż 40 Podów na start.

Bezpieczeństwo

  • OAuth 2 + OIDC — Keycloak, Azure AD, Okta; Authorization Code + PKCE dla SPA
  • BFF lub HttpOnly cookies — unikaj access token w localStorage
  • MFA — standard; polityka haseł wg NIST (długość, nie rotacja 90 dni)
  • CSP, CSRF, OWASP — baseline dla WWW
  • Secrets — Vault / AWS Secrets Manager, nie w repo
  • SBOM + skan CVE — wymagane w coraz większej liczbie RFP

Platform Engineering

Zespoł platformy dostarcza „golden path” (szablony, K8s, observability) — dev nie składa infra od zera. Backstage, wewnętrzne developer portale.

Obserwowalność

  • OpenTelemetry — jeden standard traces/metrics/logs (zastępuje własne formaty)
  • Structured logging — JSON, correlation-id przez cały request
  • Dashboards + alerty — SLO/error budget zamiast alert na każdy WARN
  • Health: liveness + readiness + startup probe (wolny Spring)

Typowe błędy wyboru

  1. Mikroserwisy przed problemem organizacyjnym — koszt K8s + sieć + distributed debug
  2. ES/Kafka „bo enterprise brzmi” — bez use case
  3. Brak standardu observability — każdy zespół inny stack
  4. Frontend bez TypeScript strict — dług rośnie niewidocznie
  5. Auth własny zamiast IdP — lata utrzymania kryptografii
  6. Ignorowanie NIST/OWASP — audyt blokuje release
  7. AI w prod bez polityki danych — compliance nightmare
  8. Zbyt wczesna optymalizacja (Graal native wszędzie) — build i debug drogie

Stack authors (przykład greenfield corp-light): Java 21+ · Spring Boot · Postgres · React · TS strict · TanStack Query · OAuth OIDC · K8s · OpenTelemetry.
