NIST — wytyczne haseł

Skrót NIST SP 800-63B (Authentication & Lifecycle Management) · hasła · passphrases · MFA
Źródło: nist.gov/800-63-3 (2017, aktualizacje do 2024)

Co to jest

NIST SP 800-63B to amerykańskie wytyczne federalne dla uwierzytelniania cyfrowego. Nie są prawem samym w sobie, ale stają się de facto standardem — wpływają na polityki haseł w firmach, bankach i IdP (Azure AD, Okta).

Główna zmiana vs „stare zasady”: długość i unikalność > wymuszona złożoność i okresowa zmiana hasła.

Zasady — co robić / czego nie

TematNIST mówi
Długość Min. 8 znaków (user-chosen). System powinien akceptować do 64 (nawet więcej). Im dłużej, tym lepiej — passphrase.
Złożoność Nie wymuszaj mixu wielkie/małe/cyfra/znak specjalny. Użytkownicy robią Haslo1! i rotują przewidywalnie.
Rotacja Nie wymuszaj zmiany co 90 dni bez powodu. Zmiana tylko gdy wyciek / kompromitacja.
Słowniki / wycieki Sprawdzaj hasło vs listy skompromitowanych (Have I Been Pwned, własna baza).
Password manager Pozwól wklejać (paste) — ułatwia długie losowe hasła.
Znaki Akceptuj wszystkie printable ASCII + Unicode (w tym spacje).
Podpowiedzi / pytania Zabronione — password hints, knowledge-based auth („imię psa”).
Blokada konta Rate limiting / throttling po błędnych próbach — niekoniecznie permanent lock bez odblokowania.
MFA Zalecane dla wyższej pewności (AAL2+) — hasło samo to AAL1.

Implementacja — praktycznie

Rejestracja / zmiana hasła

Sprawdź długość (≥8), max ≥64, lista wycieków, opcjonalnie zxcvbn (entropy score). Komunikat: „hasło znane z wycieku” zamiast reguł kompozycji.

Logowanie

Throttling (np. opóźnienie rosnące), CAPTCHA po N próbach, MFA dla wrażliwych operacji. Jednolity komunikat błędu (nie ujawniaj czy user istnieje).

Przechowywanie

NIST nie definiuje algorytmu — standard branżowy: Argon2id lub bcrypt / scrypt z solą. Nigdy plaintext, nigdy MD5/SHA1 same.

Passphrase

correct-horse-battery-staple — 4+ losowe słowa, 20+ znaków. Lepsze niż P@ssw0rd1!.

Typowe błędy

  1. Wymuszona rotacja co 90 dni → użytkownicy robią Haslo1, Haslo2
  2. Reguły złożoności → przewidywalne wzorce na końcu hasła
  3. Blokada wklejania → ludzie używają krótszych haseł
  4. Brak sprawdzania wycieków → reuse po breach
  5. Max 16 znaków → blokuje password managery

Pytania rekrutacyjne — krótkie odpowiedzi

1. Który dokument NIST o hasłach?

SP 800-63B — sekcja o memorized secrets (hasła).

2. Minimalna długość hasła wg NIST?

8 znaków (user-chosen); verifier powinien akceptować co najmniej 64.

3. Czy NIST wymaga wielkiej litery i cyfry?

Nie — odradza sztywne reguły kompozycji.

4. Czy NIST wymaga zmiany co 90 dni?

Nie — rotacja tylko przy kompromitacji.

5. Sprawdzanie haseł z wycieków?

Tak — wymagane / mocno zalecane (breached password list).

6. Paste z password managera?

Dozwolone — wręcz wspierane.

7. Password hints / pytania bezpieczeństwa?

Zabronione — zbyt łatwe do odgadnięcia.

8. Passphrase vs skomplikowane hasło?

NIST preferuje długie memorized secrets — passphrase często lepsza.

9. MFA a NIST?

Hasło = AAL1; dla wyższej pewności — MFA (AAL2/AAL3).

10. Jak hashować hasła?

NIST: approved one-way — praktycznie Argon2id, bcrypt, scrypt + salt.

11. Rate limiting?

Tak — throttling po failed attempts zamiast tylko hard lock.

12. Stare zasady vs NIST — jedna różnica?

Długość + unikalność + brak rotacji > wymuszona złożoność + 90-dniowa zmiana.
