Mapa: Twój stack → AWS

React (authors SPA)     → S3 + CloudFront
Spring Boot / Java API  → ECS Fargate / Elastic Beanstalk / Lambda
PostgreSQL + Hibernate  → RDS PostgreSQL / Aurora PostgreSQL
Redis / cache           → ElastiCache (Redis)
OAuth / OIDC            → Cognito (+ ALB auth opcjonalnie)
Pliki / upload          → S3 (+ presigned URL)
Async / events          → SQS + SNS / EventBridge
Secrets / config        → Secrets Manager / SSM Parameter Store
DNS                     → Route 53
API publiczne           → API Gateway → Lambda / ALB → ECS
Logi / metryki          → CloudWatch + X-Ray
CI/CD                   → CodePipeline + CodeBuild / GitHub Actions → ECR
Infra as code           → CloudFormation / Terraform / CDK

EKS (Kubernetes) to jedna opcja pod API — poniżej alternatywy i usługi, które z EKS i tak łączysz (RDS, S3, Cognito…).

Compute — uruchamianie kodu

EC2
→ dowolny stack: Java, Docker ręcznie, legacy

Wirtualne maszyny — pełna kontrola. Spring Boot na JAR + systemd, własny Docker Compose. Ty zarządzasz OS, patchami, skalowaniem (ASG).

ECS + Fargate
→ Spring Boot w Docker, React SSR (Node), bez zarządzania serwerem

Orkiestracja kontenerów AWS-native — prostsze niż EKS. Task definition + ALB. Fargate = serverless containers (płacisz per vCPU/RAM).

Lambda
→ krótkie funkcje, webhooks, transformacje S3, BFF lekki, scheduled jobs

FaaS — Java 21 (SnapStart dla cold start), Node, Python. Limit czasu 15 min. Integracja: API Gateway, SQS, EventBridge.

Elastic Beanstalk
→ szybki deploy Spring Boot / Tomcat / Docker — „Platform as a Service”

Wrzucasz JAR/WAR — AWS stawia EC2, LB, autoscaling. Mniej kontroli niż ECS, szybszy start niż ręczne EC2.

App Runner
→ prosty container z Git/ECR — HTTP API bez ECS config

Uproszczony hosting kontenerów z autoscaling — między Beanstalk a Fargate pod kątem prostoty.

Batch
→ długie joby Java, ETL, raporty Hibernate off-hours

Kolejki jobów na EC2/Fargate — migracje danych, nightly batch.

Storage

S3
→ statyczny React build, backupy, upload plików, data lake, artefakty CI

Object storage — nieograniczona skala. Klasy: Standard, IA, Glacier. Wersjonowanie, lifecycle, event → Lambda.

EBS
→ dysk EC2, baza na instancji (nie prod RDS)

Block storage przy VM — gp3, io2. Snapshoty → inny AZ/region.

EFS
→ współdzielony NFS — wiele EC2/ECS, shared files

Elástyczny file storage — rzadziej niż S3 w nowych architekturach.

Bazy danych i cache

RDS (PostgreSQL, MySQL, MariaDB)
→ Hibernate/JPA, Spring Data, Flyway/Liquibase

Managed relational DB — backup, Multi-AZ, read replicas. PostgreSQL = naturalny wybór pod Twój stack.

Aurora PostgreSQL
→ PostgreSQL compatible, wyższa skala odczytu, global DB

Storage auto-scale, szybsze repliki niż RDS — koszt wyższy, HA lepsze pod duży ruch.

DynamoDB
→ key-value/document, serverless, sesje, idempotency keys, event store light

NoSQL — single-digit ms, pay per request. Nie zamiennik Postgres dla relacji — inne use case.

ElastiCache (Redis / Memcached)
→ cache Hibernate second level, sesje, rate limit, React Query backend cache

Managed Redis — pub/sub, TTL. Spring Cache + Redis.

DocumentDB
→ MongoDB-compatible (legacy migracje)

Gdy masz dokumenty Mongo — nie mylić z DynamoDB.

Sieć, CDN, API

VPC
→ izolacja sieci — public/private subnets, NAT, security groups

Fundament — RDS w private subnet, ALB w public, Lambda w VPC dla DB access.

Route 53
→ DNS authors.example.com, health checks, routing policies

Hosted zones, alias na CloudFront/ALB, failover DNS.

CloudFront
→ CDN dla React (S3 origin), TLS, cache static assets

Edge locations — niskie latency SPA globalnie. OAC/OAI do S3.

ALB / NLB
→ load balancer przed ECS/EC2 — HTTPS termination, path routing

ALB = HTTP(S), WebSocket. NLB = TCP ultra-low latency. Integracja Cognito auth na ALB.

API Gateway
→ public REST/WebSocket API → Lambda, VPC Link → ECS

Throttling, API keys, JWT authorizer (Cognito), wersjonowanie API.

Tożsamość, sekrety, config

IAM
→ role dla ECS task, Lambda, CI — zero long-lived keys w kodzie

Users, roles, policies — least privilege. Instance/task role zamiast access key w JAR.

Cognito
→ OAuth 2 / OIDC dla React SPA, User Pools, social login

Alternatywa Keycloak/Auth0 — JWT dla API (Spring Resource Server). Hosted UI login.

Secrets Manager
→ hasła RDS, API keys — rotacja

Spring Cloud AWS / env z task definition — nie w repo.

Systems Manager Parameter Store
→ config niesekretny + SecureString — 12-factor config

Tańsze niż Secrets Manager dla prostych parametrów.

KMS
→ szyfrowanie S3, RDS, Secrets — własne klucze CMK

Envelope encryption — compliance (GDPR, audit).

Messaging i integracja

SQS
→ kolejka zadań — email po AuthorCreated, decoupling serwisów

Standard (at-least-once) / FIFO (ordering). Worker Lambda/ECS konsumuje.

SNS
→ pub/sub — fan-out do wielu SQS/Lambda/email

Topic → wiele subskrybentów. Event notification pattern.

EventBridge
→ event bus — reguły JSON, integracja SaaS, scheduled cron

Zamiennik cron + SNS dla event-driven — schema registry, archiwum.

MSK (Managed Kafka)
→ Kafka dla high-throughput streams, saga events

Gdy SQS za mało — ordering partitions, replay. Spring Kafka.

Step Functions
→ orchestracja saga, workflow wizualny — kompensacje

State machine wołająca Lambda/ECS — długie procesy biznesowe.

Machine Learning i LLM

Usługi AI w AWS układają się w trzy poziomy abstrakcji. Wybierasz najniższy, który wystarczy — im wyżej, tym mniej kodu i mniej kontroli.

PoziomUsługiKiedy
1. Gotowe APITextract, Comprehend, Rekognition, Transcribe…Zadanie jest standardowe (OCR, sentyment, transkrypcja) — zero wiedzy o ML
2. Modele fundamentalneBedrock, Amazon QPotrzebujesz LLM: chat, RAG, podsumowania, generowanie kodu
3. Własne modeleSageMaker AITrenujesz na własnych danych, masz zespół data science

Bedrock — z czego się składa

Bedrock to jedno API (InvokeModel / Converse) do modeli wielu dostawców, bez zarządzania infrastrukturą i bez wysyłania danych poza Twoje konto. Wokół samego wnioskowania AWS dołożył komponenty, które inaczej trzeba by pisać samodzielnie.

KomponentPo co
Converse APIJednolity interfejs czatu dla wszystkich modeli — zmiana dostawcy bez przepisywania kodu. Obsługuje streaming, obrazy i tool use (function calling)
Knowledge BasesGotowy RAG: wskazujesz źródło (S3, Confluence, SharePoint, web), Bedrock robi chunking, embeddingi, zapis do bazy wektorowej i doklejanie kontekstu do promptu
AgentsModel planuje kroki i wywołuje Twoje API (przez OpenAPI lub Lambdę) — obsługa zamówień, operacje na bazie, integracje
GuardrailsFiltry treści, blokowane tematy, wykrywanie i maskowanie PII, kontrola halucynacji względem źródła. Da się je podpiąć także do modeli spoza Bedrock
Prompt Management / FlowsWersjonowanie promptów poza kodem i wizualne łączenie kroków (prompt → Lambda → warunek → prompt)
Model EvaluationPorównanie modeli na Twoim zbiorze — automatyczne metryki, ocena przez inny model (LLM-as-a-judge) lub przez ludzi
Fine-tuning / distillation / Custom Model ImportDostrojenie modelu na własnych danych, przeniesienie wiedzy z dużego modelu do mniejszego, import własnych wag (np. dotrenowanej Llamy)
Provisioned ThroughputZarezerwowana przepustowość zamiast rozliczenia za token — przewidywalna latencja i limity dla produkcji
Batch inferencePrzetworzenie dużego zbioru offline, taniej niż wywołania on-demand
Prompt caching / routingCache powtarzalnego prefiksu promptu (tnie koszt i latencję) oraz automatyczne kierowanie prostszych zapytań do tańszego modelu
Data AutomationWyciąganie ustrukturyzowanych danych z dokumentów, obrazów, audio i wideo jednym wywołaniem
Inference profilesCross-region — rozkładają ruch na kilka regionów przy limitach przepustowości; application — pozwalają rozliczać koszty per aplikacja/zespół

Bedrock — rodziny modeli

Katalog zmienia się co kilka tygodni i różni się między regionami; poniżej rodziny, które warto znać z nazwy. Dostęp do każdej trzeba najpierw włączyć w konsoli (model access).

Mistral AILekkie i szybkie modele do zadań masowych: klasyfikacja, ekstrakcja, proste podsumowania
CohereCommand do generowania, ale głównie Embed i Rerank — poprawa trafności wyników wyszukiwania w RAG

Jak wybierać: zacznij od najtańszego modelu w rodzinie i zmierz jakość na własnych przykładach przez Model Evaluation. Przechodź wyżej dopiero, gdy metryki tego wymagają — różnica w cenie między najmniejszym a największym modelem bywa dwudziestokrotna. Do embeddingów wybieraj osobny, tani model (Titan, Cohere), nie model czatowy.

Gotowe usługi AI — bez trenowania

Textract
→ OCR ze strukturą: faktury, formularze, tabele, dokumenty tożsamości

Zwraca pola i relacje, nie tylko surowy tekst — typowe wejście do pipeline'u „dokument → JSON → baza”.

Comprehend
→ NLP: sentyment, encje, języki, wykrywanie i redakcja PII

Do klasyfikacji zgłoszeń i anonimizacji danych przed wysłaniem ich do LLM.

Rekognition
→ analiza obrazu i wideo: obiekty, twarze, moderacja treści

Weryfikacja uploadów użytkowników, wyszukiwanie po zawartości zdjęć.

Transcribe / Polly / Translate
→ mowa na tekst, tekst na mowę, tłumaczenie maszynowe

Transkrypcja spotkań i rozmów (także na żywo), lektor w aplikacji, lokalizacja treści z własnym słownikiem terminów.

Kendra / Personalize / Fraud Detector
→ wyszukiwanie po dokumentach firmowych, rekomendacje, ocena ryzyka

Gotowe modele domenowe — Kendra bywa alternatywą dla własnego RAG, gdy liczy się głównie wyszukiwanie, a nie generowanie odpowiedzi.

Amazon Q
→ asystent: Q Developer w IDE i konsoli, Q Business nad danymi firmy

Warstwa aplikacyjna nad modelami — gotowy produkt zamiast budowania własnego czatu.

SageMaker AI — własne modele

Pełen cykl życia modelu: Studio jako środowisko pracy, Ground Truth do etykietowania, Feature Store, treningi na klastrach GPU, Autopilot (AutoML), JumpStart z gotowymi modelami do dotrenowania, Pipelines dla CI/CD modeli oraz Model Monitor i Clarify do wykrywania dryfu i biasu. Wnioskowanie w czterech trybach: real-time endpoint, serverless inference, asynchroniczne (duże payloady) i batch transform.

Pułapka: endpoint SageMaker nalicza się za każdą godzinę istnienia, niezależnie od liczby zapytań — zapomniana instancja GPU po eksperymencie to najczęstsza niespodzianka na fakturze. Bedrock rozlicza się per token, więc nieużywany „nic nie kosztuje”.

RAG na własnych danych — typowa architektura

Dokumenty w S3
   ↓ (ingest, chunking, embeddingi)
Bedrock Knowledge Base → OpenSearch Serverless / Aurora pgvector
   ↑ retrieve
React → API Gateway → Lambda / ECS (Spring Boot)
                        ↓ Converse API + Guardrails
                      Bedrock (Claude / Nova)
CloudWatch — logi promptów, koszt per token

Uprawnienia załatwia rola IAM (bedrock:InvokeModel na konkretne ARN modeli) — bez kluczy API w kodzie. Dane wysłane do Bedrock nie są używane do trenowania modeli, a ruch może iść przez VPC endpoint (PrivateLink), co zwykle rozstrzyga dyskusję z działem bezpieczeństwa.
