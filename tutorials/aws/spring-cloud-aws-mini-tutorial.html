Część 0 — Fundamenty

Spring Cloud AWS to warstwa Spring Boot nad AWS SDK v2: auto-config regionu i credentials, beany klientów oraz Springowe API (S3Template, @SqsListener, spring.config.import). Nie jest to Spring Cloud Netflix (Eureka, Config Server) ani „SDK do całego AWS”.

Wersja SCASpring BootUwagi
2.x · org.springframework.cloud2.xSDK v1 — legacy; RDS/ElastiCache były tu i wyleciały
3.3 / 3.4 · io.awspring.cloud3.4 / 3.5Produkcja 2025–26 na Boot 3
4.0.x · io.awspring.cloud4.0Jackson 3, Kinesis Integration / Stream binder
Stare artefakty org.springframework.cloud:spring-cloud-starter-aws to inna era (SDK v1). Mieszanie z 3.x/4.x = dwa łańcuchy credentials i dziwne NoClassDefFoundError.

1. Kiedy używać / kiedy nie

Bierz SCAOlej SCA
Spring Boot gada z S3, SQS, SNS, DynamoDB, SES — chcesz template / @SqsListener / s3:// Resource Tylko RDS / Aurora / Postgres — JDBC URL + Hibernate; SCA nic tu nie daje (wsparcie RDS z 2.x usunięte)
Config i sekrety z Parameter Store / Secrets Manager przez spring.config.import Tylko ElastiCache / Redis — Spring Data Redis + endpoint; analogicznie usunięte z 2.x
Chcesz jeden zestaw credentials/region także pod własnego klienta SDK (Bedrock, EventBridge…) Cognito, Lambda invoke, Step Functions, Bedrock, Textract, OpenSearch — brak startera; SDK v2 albo libka domenowa
Testy na LocalStack jednym endpointem Quarkus / Micronaut / czysty servlet — to biblioteka Springowa
Metryki Micrometer → CloudWatch Lambda „hello world” i walka o każdy MB cold startu — cienki SDK / Powertools bywa lżejszy
Reguła: SCA tam, gdzie daje idiom Springa (listener, Resource, ConfigData). Tam, gdzie i tak wołasz jedno API SDK — wstrzyknij klienta z core albo stwórz beana SDK. Nie pakuj startera „na zapas” do całej chmury.
Nie-błąd: aplikacja z Hibernate + RDS bez Spring Cloud AWS. To normalny, zalecany układ. SCA nie zastępuje JDBC.

2. BOM, region, IAM

Importuj BOM, startery bez wersji. Core (spring-cloud-aws-starter) wchodzi tranzytywnie — sam wystarczy, gdy chcesz tylko auto-config credentials pod własny klient SDK.

<dependencyManagement>
  <dependencies>
    <dependency>
      <groupId>io.awspring.cloud</groupId>
      <artifactId>spring-cloud-aws-dependencies</artifactId>
      <version>3.4.0</version> <!-- Boot 4 → 4.0.x -->
      <type>pom</type><scope>import</scope>
    </dependency>
  </dependencies>
</dependencyManagement>

<dependency>
  <groupId>io.awspring.cloud</groupId>
  <artifactId>spring-cloud-aws-starter-s3</artifactId>
</dependency>
spring:
  cloud:
    aws:
      region:
        static: eu-central-1   # albo DefaultAwsRegionProviderChain (env / IMDS)
      # credentials.access-key / secret-key — TYLKO lokalnie, nigdy w git

Domyślnie DefaultCredentialsProvider (kolejność SDK): zmienne AWS_ACCESS_KEY_ID → profil ~/.aws/credentials → IRSA / web identity → credentials kontenera ECS → instance profile EC2.

ŚrodowiskoJak się logować
Laptopaws sso login / profil; nie commituj kluczy
ECS / EC2task role / instance profile — zero kluczy w YAML
EKSIRSA (service account); dodaj artefakt SDK sts pod StsWebIdentityTokenFileCredentialsProvider
CIOIDC do roli (GitHub Actions) albo krótkie klucze w secret store runnera
Brak regionu = start pada albo klienci lecą w us-east-1. Ustaw AWS_REGION / spring.cloud.aws.region.static albo polegaj na IMDS na EC2/ECS.

S3

@Service
class InvoiceStore {
  private final S3Template s3;
  InvoiceStore(S3Template s3) { this.s3 = s3; }

  void put(String id, InputStream bytes) {
    s3.store("invoices", "2026/" + id + ".pdf", bytes);
  }
  URL signedGet(String key) {
    return s3.createSignedGetURL("invoices", key, Duration.ofMinutes(15));
  }
}

@Value("s3://invoices/config/rules.json")
Resource rules;

SQS — produkcja i konsumpcja

sqsTemplate.send("orders", orderCreated);

@Component
class OrderListener {
  @SqsListener("orders")
  void on(OrderCreated event) { /* biznes */ }
}

Pułapka: SNS → SQS owija payload w JSON z polami Type/Message. Na listenerze: @SnsNotificationMessage OrderCreated event, inaczej deserializacja „nie pasuje do DTO”. FIFO wymaga MessageGroupId (i zwykle deduplikacji). @SqsListener + Spring Boot DevTools = problem classloadera — wyłącz DevTools albo nie używaj listenera lokalnie.

SNS i SES

snsTemplate.convertAndSend("order-events", event);

SimpleMailMessage mail = new SimpleMailMessage();
mail.setTo("ops@example.com");
mail.setSubject("Order " + id);
mail.setText("…");
mailSender.send(mail);

SES: zweryfikowany adres/domena w regionie klienta. Sandbox AWS odrzuci nieznanego odbiorcę — to limit konta, nie bug Springa.

DynamoDB

@DynamoDbBean
public class Person {
  private UUID id;
  private String name;
  @DynamoDbPartitionKey public UUID getId() { return id; }
  public void setId(UUID id) { this.id = id; }
  // getters/setters name…
}
dynamoDbTemplate.save(person);  // tabela domyślnie: "person"

Nazwa tabeli = snake_case klasy + opcjonalny spring.cloud.aws.dynamodb.table-prefix. To nie jest @Table z JPA. DevTools wymaga StaticTableSchema.

CloudWatch (metryki)

management:
  cloudwatch:
    metrics:
      export:
        namespace: my-app   # wymagane, bez tego auto-config nie wstanie
        step: 1m

IAM: cloudwatch:PutMetricData. Custom metryki biznesowe — zwykły Micrometer; SCA tylko eksportuje.

4. Parameter Store i Secrets Manager

To ConfigData API Boota, nie Spring Cloud Config Server. Aplikacja wciąga properties przy starcie — bez dodatkowego serwera configu.

spring:
  config:
    import:
      - optional:aws-parameterstore:/config/my-app/
      - optional:aws-secretsmanager:/secrets/my-app
Parameter StoreSecrets Manager
Po coConfig (feature flags, URL-e, limity); taniej przy dużej liczbie kluczyHasła DB, tokeny, rotacja
Formatścieżka → property; trailing / w prefixie ma znaczenieJSON (klucze → properties) albo plain text
IAM (minimum)ssm:GetParameter(s), ssm:GetParametersByPath; KMS gdy SecureStringsecretsmanager:GetSecretValue, DescribeSecret
Bez optional: brak AWS na laptopie = aplikacja nie wstaje. Z optional: lokalnie lecisz na application-local.yml, na ECS import jest obowiązkowy w profilu prod.
/config/my-app/spring.datasource.url + import z trailing slash → property spring.datasource.url. Ten sam prefix bez slashu skleja nazwy inaczej — „dziwne” puste property to zwykle slash, nie IAM.

5. Łączymy się też bez startera SCA

Core ustawia credentials/region. Reszta — własny @Bean klienta SDK albo inna biblioteka.

RDS / Aurora Postgresjdbc:postgresql://…rds.amazonaws.com + Hikari; IAM auth = plugin JDBC / token RDS, nie SCA
ElastiCache RedisSpring Data Redis, TLS, AUTH token
CognitoSpring Security OAuth2 / JWT issuer; admin API = SDK cognitoidentityprovider
EventBridgeEventBridgeClient bean (core credentials)
Lambda (wywołanie)LambdaClient; wejście do Twojej Lambdy = handler AWS, nie SCA
Bedrock / S3 Vector / TextractSDK v2; SCA nie ma warstwy
Kinesis (Boot 3 / bez 4.x)Spring Cloud Stream Kinesis binder / Spring Integration AWS — osobny projekt historycznie
OpenSearchklient OpenSearch / REST
 
@Bean
EventBridgeClient eventBridge(AwsCredentialsProvider creds,
                              AwsRegionProvider region) {
  return EventBridgeClient.builder()
      .credentialsProvider(creds)
      .region(region.getRegion())
      .build();
}

6. LocalStack i testy

Jeden endpoint na auto-configowanych klientach. Testcontainers + LocalStack albo profil local.

# application-local.yml
spring:
  cloud:
    aws:
      endpoint: http://localhost:4566
      credentials:
        access-key: test
        secret-key: test
      region:
        static: eu-central-1
      s3:
        path-style-access-enabled: true

Integracyjne testy: Testcontainers module LocalStack albo @SpringBootTest + Testcontainers. Nie wołaj prawdziwego AWS z CI bez izolowanego konta sandbox.

Nie-błąd: LocalStack nie implementuje każdej usługi 1:1 (SES, niektóre IAM/KMS). Brak feature’u w LocalStack ≠ zła konfiguracja SCA. S3/SQS/SNS/DynamoDB/SSM pokryte dobrze.

Typowe błędy

  1. Klucze w application.yml na prod. Instance profile / IRSA / OIDC. YAML z access-key wycieka w logach Actuatora i w git.
  2. Starter 2.x (stary groupId) obok 3.x. Dwa SDK, dwa łańcuchy credentials.
  3. Oczekiwanie auto-config RDS/ElastiCache. Usunięte w 3.x — JDBC i Redis ręcznie.
  4. spring.config.import bez optional: na local. Timeout / błąd startu bez VPN do AWS.
  5. AccessDenied = „SCA popsute”. Najpierw IAM (akcja + zasób + region) i SCP. SCA tylko woła SDK.
  6. SNS→SQS bez @SnsNotificationMessage. DTO nie wstaje, wygląda jak zły Jackson.
  7. FIFO bez group id / dedup. MissingParameter albo cicha utrata kolejności.
  8. Listener bez DLQ i za krótkiego visibility timeout. Ponowienia w kółko; to nie memory leak Springa.
  9. @SqsListener + DevTools. Oficjalnie zepsute classloaderem — wyłącz restart.
  10. Bucket w innym regionie niż klient. 301/redirect albo PermanentRedirect — ustaw region per-klient (spring.cloud.aws.s3.region).

Nie-błędy (wyglądają groźnie, są OK)

  • Brak SCA przy samym Postgresie na RDS — właściwy design.
  • Wstrzyknięty S3Client obok S3Template — niski poziom do CopyObject / multipart; template do CRUD i presign.
  • SQS listener „nic nie robi” przez 20 s — long polling; nie spin-wait.
  • Lokalny start bez AWS po optional: import — config z AWS po prostu nie wchodzi.
  • SES sandbox odrzuca maila — limit konta AWS, nie MailSender.
  • Parameter Store SecureString działa — SCA dekoduje; potrzebujesz kms:Decrypt.
  • Core-only + BedrockClient — legalne użycie SCA bez startera S3/SQS.
