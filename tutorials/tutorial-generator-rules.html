Źródło dla Cursor IDE: .cursor/rules/nano-tutorials.mdc + .cursor/rules/mini-tutorial-html.mdc

1. Format pliku

Jeden plik HTML — samodzielny, bez CDN, bez zewnętrznych fontów/obrazków. Działa przez podwójne kliknięcie (file://).
ElementReguła
Ścieżkatutorials/{kategoria}/{temat}-mini-tutorial.html
Kategorianp. java/, react/, architecture/, aws/, postgresql/
Nazwa plikukebab-case, sufiks -mini-tutorial.html
KodowanieUTF-8, lang="pl"
Szerokośćmax-width: 820px, wyśrodkowany body
Link wsteczOBOWIĄZKOWY — pierwszy element w <body> (przed H1): <p class="back"><a href="../index.html">← Spis tutoriali</a></p> + CSS .back / .back a

2. Struktura treści (kolejność sekcji)

Każdy tutorial ma ten sam szkielet — dostosuj sekcje merytoryczne, zachowaj układ:

  1. Link wstecz (.back) — przed wszystkim innym w body; bez tego tutorial jest niekompletny
  2. Nagłówek H1 — temat krótko
  3. Meta (.meta) — 1–2 linie: co obejmuje + „Format: HTML…” + ewent. „Bez pytań”
  4. Spis treści (.toc) — linki kotwic #sekcja
  5. Część 0 / Fundamenty — „co to jest”, jedno zdanie podsumowujące
  6. 3–7 części merytorycznych (H2) — rdzeń tematu; 2–3 z klasą must-know
  7. Typowe błędy — lista 8–10 punktów (H2)
  8. Opcjonalnie: Pytania rekrutacyjne — tylko gdy user prosi

Między większymi H2 używaj <hr>.

3. Wielkość i głębokość

WariantRozmiarKiedy
Pełny~450–550 linii HTML, 40 pytańHibernate, React, K8s, OAuth… — user chce rekrutację
Średni~350–450 linii, bez pytańDDD, architektura, Java 8–25, Postgres, AWS
Krótki~200–280 linii, 10–15 pytań maxNIST hasła, bardzo wąski temat
  • Opis pojęcia: 2–4 zdania, potem przykład kodu/SQL/diagram
  • Tabele: preferowane zamiast długich akapitów porównawczych
  • Bloki kodu: krótkie (5–15 linii), działające, z kontekstem projektu gdy sensowne
  • Nie duplikuj całej dokumentacji — ściąga must-know, nie podręcznik

4. Styl pisania

  • Język: polski, ty / bezosobowo technicznie
  • Ton: zwięźle, konkretnie — zero „w tym tutorialu dowiesz się…”
  • Nazwy techniczne: oryginalne (useQuery, jsonb, CAP) + krótkie wyjaśnienie po polsku
  • Pułapki: przy ważnych pojęciach dopisz „Pułapka:” lub sekcję błędów
  • Bez: marketingu, „daj znać jeśli chcesz”, nadmiernego boldowania

Kopiuj CSS z istniejącego tutoriala. Zmieniaj tylko --accent i opcjonalnie kolor th (tło nagłówka tabeli) — per temat:

W blokach <pre> escapuj HTML: < → &lt;, > → &gt;, & → &amp;.

7. Pytania rekrutacyjne (tylko na życzenie)

User explicite prosi → dodaj sekcję H2 „Pytania rekrutacyjne — krótkie odpowiedzi”.

  • 40 pytań — standard pełnego tutoriala
  • 3 poziomy: Junior/Mid (15), Mid/Senior (15), Pułapki (10)
  • Format .qa-item: <strong>N. Pytanie?</strong> + <p>Krótka odpowiedź.</p>
  • Odpowiedź: 1–3 zdania, bez lania wody
  • User pisze „bez pytań” / „krótko” → pomiń całą sekcję; wpisz w meta „Bez pytań rekrutacyjnych”

8. Aktualizacja index.html

Po każdym nowym tutorialu zaktualizuj tutorials/index.html:

  1. Zwiększ <span class="count">N tutoriali</span>
  2. Dodaj kartę .card w odpowiedniej sekcji H2 (Backend, Frontend, Bazy, Architektura, DevOps, Bezpieczeństwo…)
  3. Karta: href, .card-title, .card-desc (1 linia), .card-path
  4. Nowa kategoria? — dodaj nowy <h2> + .card-list

Ten plik reguł nie musi być w liczniku tutoriali merytorycznych — opcjonalnie link w stopce indexu.

9. Checklist przed zapisem

  • ☐ Plik otwiera się offline, spis treści działa (kotwice)
  • ☐ Link „← Spis tutoriali” jest pierwszym elementem w <body> (przed H1) i prowadzi do ../index.html
  • ☐ W CSS są reguły .back / .back a
  • ☐ max-width: 820px, spójny CSS z rodziną tutorials/
  • ☐ 2–3 sekcje must-know
  • ☐ Sekcja „Typowe błędy” (8–10 pkt)
  • ☐ Długość w targetcie (średni ~400 linii)
  • ☐ index.html zaktualizowany
  • ☐ Brak zewnętrznych zależności (fonty, JS, CSS linkowany)

10. Prompt gotowy do wklejenia (LLM)

Stwórz mini-tutorial HTML w projekcie nano-tutorials według reguł z:
.cursor/rules/mini-tutorial-html.mdc

Temat: {TEMAT}
Kategoria katalogu: tutorials/{kategoria}/
Nazwa pliku: {temat}-mini-tutorial.html

Wymagania:
- język polski, samodzielny HTML (CSS w pliku), max-width 820px
- OBOWIĄZKOWY link wstecz jako pierwszy element w body (przed H1):
  <p class="back"><a href="../index.html">← Spis tutoriali</a></p>
  + CSS .back / .back a
- struktura: back link, meta, spis treści, fundamenty, 4–6 sekcji merytorycznych,
  typowe błędy (8–10), {pytania: 40 / bez pytań}
- styl jak tutorials/hibernate/hibernate-mini-tutorial.html (wielkość średnia)
- zaktualizuj tutorials/index.html (licznik + karta)

Nie twórz plików markdown ani README unless asked.

Referencje wzorcowe: pełny z pytaniami → hibernate-mini-tutorial.html; średni bez pytań → ddd-mini-tutorial.html, postgresql-mini-tutorial.html; stack 3-w-1 → react-stack-mini-tutorial.html.
