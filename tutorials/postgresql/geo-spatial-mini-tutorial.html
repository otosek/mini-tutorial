0. Fundamenty GIS

Dane geoprzestrzenne to geometrie na Ziemi (lub innej powierzchni) z przypisanym układem współrzędnych. W stacku Java + Hibernate + PostgreSQL standardem jest PostGIS (rozszerzenie PG) + Hibernate Spatial + biblioteka JTS (Java Topology Suite) do obiektów geometrycznych w JVM.

POINT        — lokalizacja (sklep, GPS użytkownika)
LINESTRING   — trasa, droga, rzeka, kabel
POLYGON      — obszar (dzielnica, strefa dostawy, granica kraju)
MULTIPOLYGON — wiele obszarów (archipelag, kilka stref)
GEOMETRYCOLLECTION — mieszanka typów

SRIDSpatial Reference ID — numer układu współrzędnych. 4326 = WGS84 (GPS, lon/lat w stopniach)
WGS84 (EPSG:4326)Domyślny dla GPS, map Google/OSM, GeoJSON. Jednostki: stopnie
Web Mercator (EPSG:3857)Kafelki map (Slippy maps). Jednostki: metry — do wizualizacji, nie do precyzyjnych obliczeń na dużych odległościach

Pułapka: zamiana kolejności lon/lat. W PostGIS i GeoJSON zawsze (longitude, latitude) — czyli (X, Y). Warszawa ≈ POINT(21.01 52.23), nie odwrotnie. Błąd daje lokalizację w oceanie.

Kiedy geometry, kiedy geography? Dla punktów GPS i zapytań „w promieniu 500 m” — geography lub geometry + transformacja do metrycznego SRID (np. EPSG:2180 lub strefa CS2000 — patrz sekcja o układach polskich). Dla analizy kształtów i danych z map geodezyjnych — geometry w lokalnym SRID.

0b. Polskie układy współrzędnych

W Polsce obowiązuje Państwowy System Odniesień Przestrzennych (PSP) — rozporządzenie RM (GUGiK). Dla developera web/mobile najważniejsze są dwa poziomy: układ geodezyjny (GPS) oraz układ płaski na mapie (metry). Telefon zwraca WGS84; urzędowa mapa, geodezja i EWIDencja gruntów pracują w metrycznych układach kartograficznych.

GPS (sfera) → mapa płaska (metry)

Ziemia to elipsoida (przybliżenie kuli spłaszczonej). GPS podaje pozycję na tej powierzchni jako szerokość i długość geograficzną (stopnie). Mapa na ekranie lub w CAD to płaszczyzna w metrach — potrzebna jest projekcja kartograficzna: matematyczne „rozcięcie” i spłaszczenie fragmentu elipsoidy.

Elipsoida (ETRS89 / WGS84)          Projekcja (Gauss-Krügera / TM)
     lat/lon [°]          ST_Transform          X, Y [m] na mapie
  ┌─────────────────┐    ──────────────►    ┌─────────────────┐
  │  ● punkt GPS    │                       │  ● ten sam punkt │
  │  52.23°N        │   południk osiowy,    │  np. y≈500000   │
  │  21.01°E        │   współcz. skali,     │  x≈6300000      │
  └─────────────────┘   false easting       └─────────────────┘

Polska stosuje odwzorowanie Gaussa-Krügera (wariant Transverse Mercator): walec styczny do wybranego południka osiowego. Im dalej od tego południka (wschód–zachód kraju), tym większe zniekształcenia — dlatego przy dużych skalach kraj dzieli się na 4 strefy z różnymi południkami osiowymi.

Układy obowiązujące w Polsce

UkładEPSGZastosowanieStrefy
WGS 84 (GPS) 4326 Telefony, nawigacja, API map, GeoJSON Globalny — stopnie lon/lat
ETRS89 / ETRF2000-PL 4258 / 9702 Geodezyjny układ odniesienia w Europie i PL (kampania EUREF) Stopnie — baza dla układów płaskich
Układ „1992” (PL-1992, CS92) 2180 Mapy 1:10 000 i mniejsze skale, dane ogólnokrajowe Jedna strefa na całą Polskę
Układ „2000” (CS2000) 2176–2179 Geodezja, kataster, mapy 1:5000 i większe skale, projekty budowlane 4 strefy (5–8)

ETRS89 vs WGS84: W praktyce aplikacyjnej (dostawy, sklepy, „near me”) traktujesz je jako zgodne — różnica to centymetry. Urzędowe dane z GUGiK / WFS geoportalu mogą być w ETRF2000-PL i układzie 2000.

Układ 1992 — jedna strefa (EPSG:2180)

Cała Polska w jednej projekcji Transverse Mercator. Parametry (rozporządzenie, załącznik „1992”):

  • Południk osiowy: 19°E
  • Współczynnik skali na osi: 0,9993
  • False easting: 500 000 m, false northing: −5 300 000 m
  • Jednostki: metry; w notacji polskiej: X = northing (północ), Y = easting (wschód)

Nadaje się do aplikacji krajowych bez wyboru strefy — prostszy model danych. Dla precyzyjnej geodezji lokalnej wolą układ 2000.

Układ 2000 — cztery strefy (EPSG:2176–2179)

Kraj podzielony na 4 pasy południkowe (strefy 5–8 w nomenklaturze geodezyjnej). Każda strefa ma własny południk osiowy i false easting (prefiks Y), żeby współrzędne nie nakładały się między strefami:

StrefaEPSGPołudnik osiowyFalse easting (Y)Obszar (orientacyjnie)
5217615°E5 500 000 mZachód PL — na zachód od 16°30′E
6217718°E6 500 000 m16°30′E – 19°30′E
7217821°E7 500 000 m19°30′E – 22°30′E (m.in. Warszawa, Kraków)
8217924°E8 500 000 mWschód PL — na wschód od 22°30′E

Wspólne parametry stref 2000: współczynnik skali 0,999923, elipsoida GRS 1980, false northing 0.

Pułapka: punkt blisko granicy stref (np. 19°29′E vs 19°31′E) musi być zapisany we właściwej strefie. Zły EPSG daje pozycję setki kilometrów od rzeczywistości. Przy importie z geodezji zawsze sprawdź metadane warstwy.

Wybór strefy po długości geograficznej

-- Uproszczony wybór EPSG strefy CS2000 po lon (Java / SQL)
-- lon < 16.5  → 2176
-- lon < 19.5  → 2177
-- lon < 22.5  → 2178
-- w pozostałych → 2179

-- PostGIS: GPS Warszawy → układ 1992 (metry)
SELECT ST_AsText(
  ST_Transform(ST_SetSRID(ST_MakePoint(21.0122, 52.2297), 4326), 2180)
) AS punkt_pl_1992;

-- ten sam punkt → strefa 7 (układ 2000, Warszawa ~21°E)
SELECT ST_AsText(
  ST_Transform(ST_SetSRID(ST_MakePoint(21.0122, 52.2297), 4326), 2178)
) AS punkt_cs2000_strefa7;

-- odległość w metrach: transformuj oba punkty do tego samego SRID
SELECT ST_Distance(
  ST_Transform(a.geom, 2178),
  ST_Transform(b.geom, 2178)
) FROM ...;

ST_Transform — serce konwersji

GPS → płasko: ST_Transform(geom, 2180). Płasko → GPS: ST_Transform(geom, 4326). PostGIS używa biblioteki PROJ z definicjami EPSG. ST_SetSRID tylko „przykleja etykietę” — nie przelicza współrzędnych.

1. PostGIS — typy i tabele

CREATE EXTENSION IF NOT EXISTS postgis;

CREATE TABLE stores (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    location    geography(Point, 4326) NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE delivery_zones (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    area        geometry(Polygon, 4326) NOT NULL
);

CREATE TABLE routes (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    path        geometry(LineString, 4326) NOT NULL
);

Wstawianie danych

-- z lon/lat (WGS84)
INSERT INTO stores (name, location)
VALUES ('Sklep Centrum',
        ST_SetSRID(ST_MakePoint(21.0122, 52.2297), 4326)::geography);

-- polygon — zamknięty pierścień (pierwszy = ostatni punkt)
INSERT INTO delivery_zones (name, area)
VALUES ('Centrum',
    ST_GeomFromText(
        'POLYGON((21.00 52.22, 21.05 52.22, 21.05 52.25, 21.00 52.25, 21.00 52.22))',
        4326));

-- linia (trasa)
INSERT INTO routes (name, path)
VALUES ('Trasa A',
    ST_GeomFromText('LINESTRING(21.01 52.23, 21.02 52.24, 21.03 52.22)', 4326));

2. Zapytania przestrzenne

Odległość i „w pobliżu”

-- sklepy w promieniu 1 km od punktu użytkownika (geography → metry)
SELECT id, name,
       ST_Distance(location, ST_MakePoint(21.01, 52.23)::geography) AS dist_m
FROM stores
WHERE ST_DWithin(
    location,
    ST_SetSRID(ST_MakePoint(21.01, 52.23), 4326)::geography,
    1000   -- metry
)
ORDER BY dist_m;

ST_DWithin jest kluczowe — używa indeksu GiST (w przeciwieństwie do ST_Distance(...) < X bez operatora). ST_Distance na geography zwraca metry; na geometry(4326) — stopnie (bezużyteczne do „500 m”).

Punkt w obszarze (geofencing)

-- czy punkt użytkownika leży w strefie dostawy?
SELECT dz.name
FROM delivery_zones dz
WHERE ST_Contains(
    dz.area,
    ST_SetSRID(ST_MakePoint(21.012, 52.230), 4326)
);

-- alternatywa: ST_Within(point, polygon) — odwrotna perspektywa

Przecięcia i nakładanie

-- które trasy przecinają strefę?
SELECT r.name
FROM routes r
JOIN delivery_zones dz ON ST_Intersects(r.path, dz.area)
WHERE dz.name = 'Centrum';

-- obszar wspólny dwóch polygonów
SELECT ST_Area(ST_Intersection(a.area, b.area)) AS overlap_sq_deg
FROM delivery_zones a, delivery_zones b
WHERE a.name = 'Centrum' AND b.name = 'Żoliborz';

Operatory przestrzenne

Operator / funkcjaZnaczenie
ST_Contains(A, B)A zawiera B (polygon zawiera punkt)
ST_Within(A, B)A leży w B
ST_Intersects(A, B)Mają wspólny punkt/linię/obszar
ST_Touches(A, B)Dotykają się, bez nakładania wnętrza
ST_DWithin(A, B, d)Odległość ≤ d (indeksowalne)
ST_Distance(A, B)Odległość (metry na geography)
A && BBounding box się przecina — szybki prefiltr (używa indeksu)

3. Indeksy przestrzenne

Bez indeksu GiST/SP-GiST zapytania „w pobliżu” robią sequential scan — przy milionach punktów to katastrofa.

CREATE INDEX idx_stores_location ON stores USING GIST (location);
CREATE INDEX idx_zones_area ON delivery_zones USING GIST (area);
CREATE INDEX idx_routes_path ON routes USING GIST (path);
GiST

Generalized Search Tree — domyślny dla geometrii. Obsługuje &&, ST_Intersects, ST_DWithin (z odpowiednim operatorem).

SP-GiST

Alternatywa — czasem lepsza dla punktów; testuj EXPLAIN na własnych danych.

EXPLAIN (ANALYZE, BUFFERS)
SELECT id FROM stores
WHERE location && ST_Expand(ST_MakePoint(21.01, 52.23)::geography, 1000)
  AND ST_DWithin(location, ST_MakePoint(21.01, 52.23)::geography, 1000);
-- oczekuj: Index Scan using idx_stores_location

Pułapka: indeks na wyrażeniu ST_Transform(location::geometry, 2180) — jeśli filtrujesz w innym SRID niż kolumna, indeks musi być na tym samym wyrażeniu co WHERE.

3. Hibernate Spatial

hibernate-spatial mapuje typy PostGIS na obiekty JTS w encjach JPA. Wymaga dialektu PostGIS i zależności w Maven/Gradle.

<!-- pom.xml -->
<dependency>
    <groupId>org.hibernate.orm</groupId>
    <artifactId>hibernate-spatial</artifactId>
</dependency>
<dependency>
    <groupId>org.locationtech.jts</groupId>
    <artifactId>jts-core</artifactId>
    <version>1.19.0</version>
</dependency>
// application.properties
spring.jpa.properties.hibernate.dialect=org.hibernate.spatial.dialect.postgis.PostgisPG10Dialect
// lub nowszy: PostgisDialect (Hibernate 6+)

Encja z punktem i polygonem

@Entity
@Table(name = "stores")
public class Store {

    @Id
    private UUID id;

    private String name;

    @Column(columnDefinition = "geography(Point,4326)")
    private Point location;   // org.locationtech.jts.geom.Point

    // getter/setter
}

@Entity
@Table(name = "delivery_zones")
public class DeliveryZone {

    @Id
    private UUID id;

    private String name;

    @Column(columnDefinition = "geometry(Polygon,4326)")
    private Polygon area;
}

Hibernate Spatial automatycznie konwertuje Point, LineString, Polygon, MultiPolygon z JTS ↔ PostGIS. Tworzenie w kodzie:

GeometryFactory gf = new GeometryFactory(new PrecisionModel(), 4326);
Point warsaw = gf.createPoint(new Coordinate(21.0122, 52.2297));
// Coordinate(x=lon, y=lat)

store.setLocation(warsaw);

Repository — native query vs JPQL

Standardowy JPQL nie zna ST_DWithin. Typowe podejścia:

public interface StoreRepository extends JpaRepository<Store, UUID> {

    @Query(value = """
        SELECT * FROM stores s
        WHERE ST_DWithin(
            s.location,
            ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography,
            :radiusMeters
        )
        ORDER BY ST_Distance(s.location,
            ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography)
        LIMIT :limit
        """, nativeQuery = true)
    List<Store> findNearby(
        @Param("lon") double lon,
        @Param("lat") double lat,
        @Param("radiusMeters") double radius,
        @Param("limit") int limit);
}

Hibernate 6.2+ ma eksperymentalne wsparcie spatial w HQL (within, distance) — sprawdź wersję; w produkcji nadal często native SQL lub SpatialPredicate z Criteria API.

4. Warstwa Java

JTS — Java Topology Suite

jts-core to kanoniczna biblioteka geometrii w JVM. Hibernate Spatial używa jej typów; możesz też budować geometrie poza encją (walidacja, merge stref).

GeometryFactory gf = new GeometryFactory(new PrecisionModel(), 4326);

// polygon ze współrzędnych
Coordinate[] ring = {
    new Coordinate(21.00, 52.22),
    new Coordinate(21.05, 52.22),
    new Coordinate(21.05, 52.25),
    new Coordinate(21.00, 52.25),
    new Coordinate(21.00, 52.22)  // zamknięcie
};
Polygon zone = gf.createPolygon(ring);

// walidacja
if (!zone.isValid()) {
    zone = (Polygon) zone.buffer(0);  // często naprawia self-intersection
}

GeoJSON w API (Spring)

// DTO dla frontendu map
public record GeoJsonPoint(double lon, double lat) {}

public record StoreDto(UUID id, String name, GeoJsonPoint location) {
    static StoreDto from(Store s) {
        Point p = s.getLocation();
        return new StoreDto(s.getId(), s.getName(),
            new GeoJsonPoint(p.getX(), p.getY()));
    }
}

// lub biblioteka: jackson-datatype-jts, geolatte-geojson

geometry vs geography — decyzja

  • geography — promień w metrach, odległości globalne, prostsze API dla „near me”
  • geometry — analiza kształtów, powierzchni, overlay; przy metrach użyj lokalnego SRID (PL: 2180) lub ST_Transform
  • Nie mieszaj typów w jednym wyrażeniu bez rzutowania: geom::geography

Alternatywy (kiedy nie PostGIS)

lat/lon jako kolumny + formuła Haversine

Proste, bez rozszerzenia — OK dla małej skali i braku polygonów. Brak indeksu przestrzennego, brak ST_Contains.

Elasticsearch geo_point / geo_shape

Search + geo — gdy dane już w ES; PG pozostaje source of truth.

Typowe błędy

  1. Lon/lat zamienione — najczęstszy błąd; punkt ląduje w Afryce zamiast w Polsce
  2. ST_Distance na geometry(4326) w metrach — wynik w stopniach; użyj geography lub transformacji
  3. Brak SRID — ST_MakePoint bez ST_SetSRID → SRID 0, zapytania spatial failują lub dają złe wyniki
  4. Niezamknięty polygon — pierwszy wierzchołek ≠ ostatni; ST_IsValid = false
  5. Self-intersecting polygon — „krawędź się przecina”; napraw ST_MakeValid / buffer(0)
  6. ST_Distance w WHERE zamiast ST_DWithin — pełny scan; ST_DWithin korzysta z GiST
  7. Brak indeksu GiST na kolumnie geo — wolne „near me” przy dużej tabeli
  8. Mieszanie geometry i geography w jednym wyrażeniu bez jawnego cast
  9. Hibernate bez dialektu PostGIS — kolumna zapisana jako bytea lub błąd mapowania
  10. Coordinate w JTS — x = lon, y = lat; mylenie z „latitude first” z CSV
  11. Zły SRID polski — zła strefa CS2000 (2176–2179) lub mieszanie układu 1992 (2180) z 2000 bez ST_Transform

Pytania rekrutacyjne — krótkie odpowiedzi

Junior / Mid

1. Co to jest PostGIS?

Rozszerzenie PostgreSQL dodające typy i funkcje geoprzestrzenne — punkty, linie, polygony, indeksy GiST, zapytania „w pobliżu”.

2. Jaka jest kolejność współrzędnych w PostGIS i GeoJSON?

(longitude, latitude) — czyli (X, Y). Warszawa: POINT(21.01 52.23).

3. Co to jest SRID?

Spatial Reference ID — numer układu współrzędnych. 4326 = WGS84 (GPS, stopnie).

4. Czym różni się geometry od geography w PostGIS?

geometry — płaska geometria w układzie SRID (szybsze operacje). geography — sfera Ziemi, odległości w metrach.

5. Jakie typy geometrii obsługuje PostGIS?

Point, LineString, Polygon, MultiPoint, MultiLineString, MultiPolygon, GeometryCollection.

6. Jak wstawić punkt z lon/lat do tabeli?

ST_SetSRID(ST_MakePoint(lon, lat), 4326) — opcjonalnie rzutowanie na ::geography.

7. Co robi ST_DWithin?

Zwraca true, gdy dwie geometrie są w odległości ≤ podanego progu. Kluczowe do zapytań „w promieniu X m” — indeksowalne.

8. Co robi ST_Contains?

Sprawdza, czy geometria A zawiera B — np. polygon strefy dostawy zawiera punkt adresu.

9. Po co indeks GiST na kolumnie geo?

Bez niego zapytania przestrzenne robią sequential scan. GiST przyspiesza ST_DWithin, ST_Intersects, operator &&.

10. Co to jest WGS84 i jak ma się do ETRS89 w Polsce?

WGS84 (EPSG:4326) — globalny układ GPS w stopniach. ETRS89/ETRF2000-PL — europejski/polski układ geodezyjny (baza pod układy 1992 i 2000). W aplikacjach webowych praktycznie traktujesz je jako zgodne (różnica ~cm).

11. Czym jest Hibernate Spatial?

Moduł Hibernate mapujący typy PostGIS na obiekty JTS (Point, Polygon itd.) w encjach JPA.

12. Co to jest JTS?

Java Topology Suite — biblioteka geometrii w JVM (org.locationtech.jts.geom). Używana przez Hibernate Spatial.

13. Jak w encji JPA zmapować punkt GPS?

Pole typu Point (JTS) z @Column(columnDefinition = "geography(Point,4326)") + dialekt PostGIS.

14. Co to jest geofencing?

Sprawdzenie, czy punkt (użytkownik, adres) leży w zdefiniowanym obszarze — ST_Contains(zone, point).

15. Jak wyeksportować geometrię do GeoJSON z PostGIS?

ST_AsGeoJSON(geom) — zwraca JSON gotowy do API / mapy frontendowej.

Mid / Senior

16. Dlaczego ST_Distance(geom, geom) na geometry(4326) nie daje metrów?

SRID 4326 ma jednostki w stopniach. Użyj geography, ST_Transform do metrycznego SRID (np. 2180, 3857) lub ST_DistanceSphere.

17. ST_DWithin vs ST_Distance(...) < X w WHERE?

ST_DWithin jest zoptymalizowane pod indeks GiST. Samo ST_Distance w WHERE często wymusza pełny scan.

18. Kiedy użyć geometry zamiast geography w Polsce?

Geography — globalne „near me” w metrach z GPS. Geometry w EPSG:2180 (układ 1992) lub 2176–2179 (CS2000) — dane z map geodezyjnych, powierzchnie i bufor w metrach na dużych obszarach PL.

19. Co robi ST_Transform vs ST_SetSRID?

ST_SetSRID tylko przypisuje numer SRID (bez przeliczenia współrzędnych). ST_Transform rzeczywiście przelicza między układami.

20. Jak zrobić zapytanie „najbliższe N sklepów” w PostGIS?

ST_DWithin + ORDER BY ST_Distance(...) + LIMIT N. Indeks GiST na kolumnie lokalizacji obowiązkowy przy skali.

21. Dlaczego polygon musi być „zamknięty”?

Pierwszy wierzchołek musi równać się ostatniemu — inaczej ST_IsValid = false i operacje przestrzenne dają błędne wyniki.

22. Co to jest self-intersecting polygon?

Polygon, którego krawędzie się przecinają (kształt „kielicha”). Naprawa: ST_MakeValid lub buffer(0) w JTS/PostGIS.

23. Jak w Hibernate wykonać zapytanie spatial (ST_DWithin)?

Standardowy JPQL nie zna funkcji PostGIS — native query z @Query(nativeQuery = true) lub Criteria API ze spatial predicates (Hibernate 6.2+).

24. Jaki dialekt Hibernate dla PostGIS?

org.hibernate.spatial.dialect.postgis.PostgisDialect (Hibernate 6) lub starszy PostgisPG10Dialect.

25. Co robi operator && w PostGIS?

Bounding-box overlap — szybki prefiltr przestrzenny korzystający z indeksu GiST przed dokładniejszymi testami.

26. ST_Intersects vs ST_Contains?

ST_Intersects — dowolne nakładanie (punkt, linia, część obszaru). ST_Contains — A w całości zawiera B (włącznie z brzegiem).

27. Kiedy Haversine w Java zamiast PostGIS?

Mała skala, brak polygonów, proste „odległość między dwoma punktami” bez rozszerzenia PG. Nie zastąpi geofencingu ani indeksów.

28. Czym różni się układ 1992 (EPSG:2180) od układu 2000 (2176–2179)?

1992 — jedna strefa na całą Polskę, południk 19°E, mapy 1:10 000 i mniejsze. 2000 — 4 strefy (południki 15/18/21/24°E), geodezja i mapy 1:5000+, mniejsze zniekształcenia lokalnie.

29. Jak zapisać polygon narysowany na mapie (GeoJSON) w PG?

ST_GeomFromGeoJSON(text) w SQL lub parser JTS po stronie Java → encja z polem Polygon.

30. Co robi ST_Buffer?

Tworzy obszar wokół geometrii — okrąg wokół punktu, „korytarz” wokół linii. Promień w jednostkach SRID (metry po transformacji).

Pułapki / tricky

31. Czy ST_MakePoint(52.23, 21.01) to Warszawa?

Nie — to zamienione lon/lat. Poprawnie: ST_MakePoint(21.01, 52.23) (X=lon, Y=lat).

32. Czy ST_SetSRID(geom, 4326) przelicza współrzędne z 2180?

Nie — tylko zmienia metadane SRID. Do przeliczenia użyj ST_Transform(geom, 4326).

33. Czy GiST na geometry działa dla zapytania na geography?

Indeks jest na typie kolumny. Cast ::geography w WHERE może uniemożliwić użycie indeksu — trzymaj spójny typ kolumny i zapytania.

34. Czy w JTS Coordinate(lat, lon) jest poprawne?

Nie — konstruktor to Coordinate(x, y) = (lon, lat). Zamiana psuje lokalizację tak samo jak w SQL.

35. Czy Web Mercator (3857) nadaje się do obliczania odległości w metrach?

Na małych obszarach przybliżenie OK; na dużych odległościach i wysokich szerokościach geograficznych błąd rośnie. Lepiej geography lub lokalny SRID.

36. Czy ST_Contains(polygon, point) zwraca true dla punktu na brzegu?

Tak — w OGC model Contains obejmuje brzeg. Dla „tylko wnętrze” użyj ST_Covers / topologicznych wariantów zależnie od wymagań.

37. Czy Hibernate Spatial działa bez CREATE EXTENSION postgis?

Nie — baza musi mieć zainstalowane rozszerzenie PostGIS; inaczej typy geometry/geography nie istnieją.

38. Czy ST_DWithin z progiem 1000 na geometry(4326) to 1000 metrów?

Nie — to ~1000 stopni (~111 000 km przy równiku). Dla metrów użyj geography lub transformacji do metrycznego SRID.

39. W jakiej strefie CS2000 leży Warszawa (~21°E)?

Strefa 7 — EPSG:2178 (południk osiowy 21°E, false easting 7 500 000 m). Granice stref: <16°30′ → 2176, <19°30′ → 2177, <22°30′ → 2178, dalej → 2179.

40. Czy ST_Simplify zawsze zachowuje topologię?

Nie — agresywne uproszczenie może tworzyć self-intersection lub zmieniać relacje contains/intersects. Waliduj ST_IsValid po simplify.
