0. Fundamenty GIS

Dane geoprzestrzenne to geometrie na Ziemi (lub innej powierzchni) z przypisanym układem współrzędnych. W stacku Java + Hibernate + PostgreSQL standardem jest PostGIS (rozszerzenie PG) + Hibernate Spatial + biblioteka JTS (Java Topology Suite) do obiektów geometrycznych w JVM.

POINT        — lokalizacja (sklep, GPS użytkownika)
LINESTRING   — trasa, droga, rzeka, kabel
POLYGON      — obszar (dzielnica, strefa dostawy, granica kraju)
MULTIPOLYGON — wiele obszarów (archipelag, kilka stref)
GEOMETRYCOLLECTION — mieszanka typów
PojęcieZnaczenie
SRIDSpatial Reference ID — numer układu współrzędnych. 4326 = WGS84 (GPS, lon/lat w stopniach)
WGS84 (EPSG:4326)Domyślny dla GPS, map Google/OSM, GeoJSON. Jednostki: stopnie
Web Mercator (EPSG:3857)Kafelki map (Slippy maps). Jednostki: metry — do wizualizacji, nie do precyzyjnych obliczeń na dużych odległościach
geometryTyp PostGIS — płaska geometria w układzie SRID. Szybsze operacje, ale odległość w stopniach (4326) jest myląca
geographyTyp PostGIS — sferyczna powierzchnia Ziemi. Odległości w metrach (dokładniejsze „w pobliżu” na całym globie)
EWKT / WKTFormat tekstowy: SRID=4326;POINT(21.01 52.23) — lon przed lat (X przed Y)
GeoJSONJSON z geometrią — API REST, frontend map. Kolejność współrzędnych: [lon, lat]
Pułapka: zamiana kolejności lon/lat. W PostGIS i GeoJSON zawsze (longitude, latitude) — czyli (X, Y). Warszawa ≈ POINT(21.01 52.23), nie odwrotnie. Błąd daje lokalizację w oceanie.

Kiedy geometry, kiedy geography? Dla punktów GPS i zapytań „w promieniu 500 m” — geography lub geometry + transformacja do metrycznego SRID (np. 3857, 2180 dla Polski). Dla analizy kształtów, overlay map administracyjnych w jednym układzie — często geometry w lokalnym SRID (EPSG:2180 — PUWG 1992).

1. PostGIS — typy i tabele

CREATE EXTENSION IF NOT EXISTS postgis;

CREATE TABLE stores (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    location    geography(Point, 4326) NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE delivery_zones (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    area        geometry(Polygon, 4326) NOT NULL
);

CREATE TABLE routes (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    name        text NOT NULL,
    path        geometry(LineString, 4326) NOT NULL
);

Wstawianie danych

-- z lon/lat (WGS84)
INSERT INTO stores (name, location)
VALUES ('Sklep Centrum',
        ST_SetSRID(ST_MakePoint(21.0122, 52.2297), 4326)::geography);

-- polygon — zamknięty pierścień (pierwszy = ostatni punkt)
INSERT INTO delivery_zones (name, area)
VALUES ('Centrum',
    ST_GeomFromText(
        'POLYGON((21.00 52.22, 21.05 52.22, 21.05 52.25, 21.00 52.25, 21.00 52.22))',
        4326));

-- linia (trasa)
INSERT INTO routes (name, path)
VALUES ('Trasa A',
    ST_GeomFromText('LINESTRING(21.01 52.23, 21.02 52.24, 21.03 52.22)', 4326));

2. Zapytania przestrzenne

Odległość i „w pobliżu”

-- sklepy w promieniu 1 km od punktu użytkownika (geography → metry)
SELECT id, name,
       ST_Distance(location, ST_MakePoint(21.01, 52.23)::geography) AS dist_m
FROM stores
WHERE ST_DWithin(
    location,
    ST_SetSRID(ST_MakePoint(21.01, 52.23), 4326)::geography,
    1000   -- metry
)
ORDER BY dist_m;

ST_DWithin jest kluczowe — używa indeksu GiST (w przeciwieństwie do ST_Distance(...) < X bez operatora). ST_Distance na geography zwraca metry; na geometry(4326) — stopnie (bezużyteczne do „500 m”).

Punkt w obszarze (geofencing)

-- czy punkt użytkownika leży w strefie dostawy?
SELECT dz.name
FROM delivery_zones dz
WHERE ST_Contains(
    dz.area,
    ST_SetSRID(ST_MakePoint(21.012, 52.230), 4326)
);

-- alternatywa: ST_Within(point, polygon) — odwrotna perspektywa

Przecięcia i nakładanie

-- które trasy przecinają strefę?
SELECT r.name
FROM routes r
JOIN delivery_zones dz ON ST_Intersects(r.path, dz.area)
WHERE dz.name = 'Centrum';

-- obszar wspólny dwóch polygonów
SELECT ST_Area(ST_Intersection(a.area, b.area)) AS overlap_sq_deg
FROM delivery_zones a, delivery_zones b
WHERE a.name = 'Centrum' AND b.name = 'Żoliborz';

Operatory przestrzenne

Operator / funkcjaZnaczenie
ST_Contains(A, B)A zawiera B (polygon zawiera punkt)
ST_Within(A, B)A leży w B
ST_Intersects(A, B)Mają wspólny punkt/linię/obszar
ST_Touches(A, B)Dotykają się, bez nakładania wnętrza
ST_DWithin(A, B, d)Odległość ≤ d (indeksowalne)
ST_Distance(A, B)Odległość (metry na geography)
A && BBounding box się przecina — szybki prefiltr (używa indeksu)

3. Indeksy przestrzenne

Bez indeksu GiST/SP-GiST zapytania „w pobliżu” robią sequential scan — przy milionach punktów to katastrofa.

CREATE INDEX idx_stores_location ON stores USING GIST (location);
CREATE INDEX idx_zones_area ON delivery_zones USING GIST (area);
CREATE INDEX idx_routes_path ON routes USING GIST (path);
GiST

Generalized Search Tree — domyślny dla geometrii. Obsługuje &&, ST_Intersects, ST_DWithin (z odpowiednim operatorem).

SP-GiST

Alternatywa — czasem lepsza dla punktów; testuj EXPLAIN na własnych danych.

EXPLAIN (ANALYZE, BUFFERS)
SELECT id FROM stores
WHERE location && ST_Expand(ST_MakePoint(21.01, 52.23)::geography, 1000)
  AND ST_DWithin(location, ST_MakePoint(21.01, 52.23)::geography, 1000);
-- oczekuj: Index Scan using idx_stores_location

Pułapka: indeks na wyrażeniu ST_Transform(location::geometry, 2180) — jeśli filtrujesz w innym SRID niż kolumna, indeks musi być na tym samym wyrażeniu co WHERE.

3. Hibernate Spatial

hibernate-spatial mapuje typy PostGIS na obiekty JTS w encjach JPA. Wymaga dialektu PostGIS i zależności w Maven/Gradle.

<!-- pom.xml -->
<dependency>
    <groupId>org.hibernate.orm</groupId>
    <artifactId>hibernate-spatial</artifactId>
</dependency>
<dependency>
    <groupId>org.locationtech.jts</groupId>
    <artifactId>jts-core</artifactId>
    <version>1.19.0</version>
</dependency>
// application.properties
spring.jpa.properties.hibernate.dialect=org.hibernate.spatial.dialect.postgis.PostgisPG10Dialect
// lub nowszy: PostgisDialect (Hibernate 6+)

Encja z punktem i polygonem

@Entity
@Table(name = "stores")
public class Store {

    @Id
    private UUID id;

    private String name;

    @Column(columnDefinition = "geography(Point,4326)")
    private Point location;   // org.locationtech.jts.geom.Point

    // getter/setter
}

@Entity
@Table(name = "delivery_zones")
public class DeliveryZone {

    @Id
    private UUID id;

    private String name;

    @Column(columnDefinition = "geometry(Polygon,4326)")
    private Polygon area;
}

Hibernate Spatial automatycznie konwertuje Point, LineString, Polygon, MultiPolygon z JTS ↔ PostGIS. Tworzenie w kodzie:

GeometryFactory gf = new GeometryFactory(new PrecisionModel(), 4326);
Point warsaw = gf.createPoint(new Coordinate(21.0122, 52.2297));
// Coordinate(x=lon, y=lat)

store.setLocation(warsaw);

Repository — native query vs JPQL

Standardowy JPQL nie zna ST_DWithin. Typowe podejścia:

public interface StoreRepository extends JpaRepository<Store, UUID> {

    @Query(value = """
        SELECT * FROM stores s
        WHERE ST_DWithin(
            s.location,
            ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography,
            :radiusMeters
        )
        ORDER BY ST_Distance(s.location,
            ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography)
        LIMIT :limit
        """, nativeQuery = true)
    List<Store> findNearby(
        @Param("lon") double lon,
        @Param("lat") double lat,
        @Param("radiusMeters") double radius,
        @Param("limit") int limit);
}

Hibernate 6.2+ ma eksperymentalne wsparcie spatial w HQL (within, distance) — sprawdź wersję; w produkcji nadal często native SQL lub SpatialPredicate z Criteria API.

4. Warstwa Java

JTS — Java Topology Suite

jts-core to kanoniczna biblioteka geometrii w JVM. Hibernate Spatial używa jej typów; możesz też budować geometrie poza encją (walidacja, merge stref).

GeometryFactory gf = new GeometryFactory(new PrecisionModel(), 4326);

// polygon ze współrzędnych
Coordinate[] ring = {
    new Coordinate(21.00, 52.22),
    new Coordinate(21.05, 52.22),
    new Coordinate(21.05, 52.25),
    new Coordinate(21.00, 52.25),
    new Coordinate(21.00, 52.22)  // zamknięcie
};
Polygon zone = gf.createPolygon(ring);

// walidacja
if (!zone.isValid()) {
    zone = (Polygon) zone.buffer(0);  // często naprawia self-intersection
}

GeoJSON w API (Spring)

// DTO dla frontendu map
public record GeoJsonPoint(double lon, double lat) {}

public record StoreDto(UUID id, String name, GeoJsonPoint location) {
    static StoreDto from(Store s) {
        Point p = s.getLocation();
        return new StoreDto(s.getId(), s.getName(),
            new GeoJsonPoint(p.getX(), p.getY()));
    }
}

// lub biblioteka: jackson-datatype-jts, geolatte-geojson

Przepływ typowy w Spring Boot

REST (lon, lat, radius) → serwis → StoreRepository.findNearby()
                                      ↓
                              PostGIS ST_DWithin + GiST
                                      ↓
                              List<Store> → DTO z GeoJSON → mapa (Leaflet/Mapbox)

Dla zapisu strefy z mapy (rysowany polygon): frontend wysyła GeoJSON → ST_GeomFromGeoJSON w SQL lub parser JTS → encja DeliveryZone.

geometry vs geography — decyzja

  • geography — promień w metrach, odległości globalne, prostsze API dla „near me”
  • geometry — analiza kształtów, powierzchni, overlay; przy metrach użyj lokalnego SRID (PL: 2180) lub ST_Transform
  • Nie mieszaj typów w jednym wyrażeniu bez rzutowania: geom::geography

Alternatywy (kiedy nie PostGIS)

lat/lon jako kolumny + formuła Haversine

Proste, bez rozszerzenia — OK dla małej skali i braku polygonów. Brak indeksu przestrzennego, brak ST_Contains.

Elasticsearch geo_point / geo_shape

Search + geo — gdy dane już w ES; PG pozostaje source of truth.

Typowe błędy

  1. Lon/lat zamienione — najczęstszy błąd; punkt ląduje w Afryce zamiast w Polsce
  2. ST_Distance na geometry(4326) w metrach — wynik w stopniach; użyj geography lub transformacji
  3. Brak SRID — ST_MakePoint bez ST_SetSRID → SRID 0, zapytania spatial failują lub dają złe wyniki
  4. Niezamknięty polygon — pierwszy wierzchołek ≠ ostatni; ST_IsValid = false
  5. Self-intersecting polygon — „krawędź się przecina”; napraw ST_MakeValid / buffer(0)
  6. ST_Distance w WHERE zamiast ST_DWithin — pełny scan; ST_DWithin korzysta z GiST
  7. Brak indeksu GiST na kolumnie geo — wolne „near me” przy dużej tabeli
  8. Mieszanie geometry i geography w jednym wyrażeniu bez jawnego cast
  9. Hibernate bez dialektu PostGIS — kolumna zapisana jako bytea lub błąd mapowania
  10. Coordinate w JTS — x = lon, y = lat; mylenie z „latitude first” z CSV
