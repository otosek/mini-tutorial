Część 1 — Fundamenty

1.1 Co to jest React

React to biblioteka UI do budowy interfejsów z komponentów. Nie jest frameworkiem full-stack — sam React to warstwa widoku. Routing, dane, formularze dokładasz osobno (React Router, TanStack Query, React Hook Form — jak w projekcie authors).

1.2 Deklaratywny model

Opisujesz jak UI ma wyglądać dla danego stanu, a React synchronizuje DOM z tym opisem. Zmiana stanu → re-render → diff → aktualizacja DOM tylko tam, gdzie trzeba.

1.3 Single Page Application (SPA)

React działa w przeglądarce — nawigacja bez pełnego przeładowania strony (React Router). Serwer zwraca index.html + JS bundle; dalsze „strony” to zamiana komponentów.

Część 2 — Komponenty i JSX

2.1 Komponent funkcyjny

type AuthorCardProps = {
  firstName: string
  lastName: string
}

export function AuthorCard({ firstName, lastName }: AuthorCardProps) {
  return <p>{firstName} {lastName}</p>
}

Komponent to funkcja zwracająca JSX. Od React 19 — jedyny zalecany styl (class components to legacy).

2.2 JSX

Składnia przypominająca HTML w JS. Kompiluje się do React.createElement (lub jsx runtime). Jedna korzeń lub fragment <>...</>.

// Wyrażenia w klamrach
<h1>{authors.length} autorów</h1>

// Warunkowo
{authors.length > 0 && <ul>...</ul>}

// Lista — key!
{authors.map(a => <li key={a.id}>{a.firstName}</li>)}

2.3 Props — tylko w dół

Dane płyną z rodzica do dziecka przez props. Props są readonly — dziecko nie mutuje propsów rodzica. Callback w props = komunikacja w górę (onSubmit).

Część 3 — Stan i props

3.1 useState

const [selectedAuthor, setSelectedAuthor] = useState<Author | null>(null)

setSelectedAuthor(author)       // zamiana stanu
setSelectedAuthor(null)         // reset

Stan jest lokalny dla komponentu. Po odmontowaniu (AuthorsPage → wyjście z route) — stan znika. Stąd potrzeba React Query / global state dla danych współdzielonych.

3.2 State vs props

PropsState
ŹródłoRodzicWewnątrz komponentu
MutacjaReadonlyPrzez setter
PrzykładdefaultValues w formularzuselectedAuthor w AuthorsPage

3.3 Lifting state up

Gdy dwa rodzeństwa muszą współdzielić stan — podnieś stan do wspólnego rodzica i przekaż props + callback w dół.

3.4 Controlled vs uncontrolled

Controlled — React trzyma wartość inputa w state (value + onChange). Uncontrolled — DOM trzyma wartość (ref). React Hook Form domyślnie bliżej uncontrolled (mniej re-renderów).

Część 4 — Hooks

4.1 Zasady hooks

  1. Wywołuj tylko na top level — nie w if/pętli
  2. Tylko w komponentach funkcyjnych lub custom hooks

4.2 useEffect

useEffect(() => {
  document.title = `${authors.length} autorów`
}, [authors.length])   // dependency array

useEffect(() => {
  const sub = subscribe(id)
  return () => sub.unsubscribe()   // cleanup
}, [id])

Synchronizacja z systemem zewnętrznym — DOM, API, subskrypcje, timery. Nie do pochodnego stanu (lepiej wyliczyć w renderze). Pusta tablica [] = raz po mount (Strict Mode w dev wywoła 2×).

4.3 Najważniejsze hooks

HookPo co
useStateStan lokalny
useEffectEfekty uboczne, sync z zewnętrznym
useRefReferencja DOM / mutable value bez re-render
useMemoMemoizacja wartości (kosztowne obliczenie)
useCallbackMemoizacja funkcji (stabilna referencja)
useContextDane z Context bez prop drilling
useReducerZłożony stan z akcjami (alternatywa useState)

4.4 Custom hooks

// useAuthors.ts — logika wyciągnięta z komponentu
export function useAuthors() {
  const authorsQuery = useQuery({ ... })
  const saveAuthorMutation = useMutation({ ... })
  return { authors: authorsQuery.data ?? [], saveAuthor: ... }
}

Custom hook = funkcja zaczynająca się od use, może wołać inne hooks. Wzorzec na logikę wielokrotnego użytku.

Część 5 — Renderowanie i cykl życia

5.1 Reconciliation i key

React porównuje drzewo wirtualne. key identyfikuje element w liście — stabilny, unikalny (np. author.id). Index jako key — bug przy reorder/delete/insert.

5.2 Mount → update → unmount

Mount — komponent pojawia się (np. wejście na /authors). Update — zmiana state/props → re-render. Unmount — wyjście z route, cleanup w useEffect.

5.3 Strict Mode (dev)

<StrictMode> w main.tsx — w dev podwójne mount/unmount i double invoke effects, żeby wykryć brak cleanup. Tylko development, nie prod.

5.4 Batch updates

React 18+ automatycznie grupuje setState w jednym evencie — jeden re-render. Async też (po fetch w then).

Część 6 — Formularze, dane, routing (Twój stack)

React Hook Form + Zod

const { register, handleSubmit, formState: { errors } } = useForm({
  resolver: zodResolver(authorSchema),
  defaultValues,
})

<input {...register('firstName')} />

RHF — minimalne re-rendery, rejestracja pól przez register. Zod — walidacja; zodResolver łączy z RHF. Błędy w formState.errors.

TanStack Query (React Query)

const authorsQuery = useQuery({
  queryKey: ['authors'],
  queryFn: () => authorList.getAll(),
})

const mutation = useMutation({
  mutationFn: save,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['authors'] }),
})

Serwerowy stan — cache, refetch, loading/error. QueryClientProvider w main.tsx. Po wyjściu z route dane zostają w cache (w przeciwieństwie do useState).

React Router

// router.tsx
{ path: 'authors', element: <AuthorsPage /> }

// RootLayout
<NavLink to="/authors">Authors</NavLink>
<Outlet />   // tu renderuje się child route

Routing deklaratywny — URL → komponent. Outlet — miejsce na zagnieżdżone trasy. Zmiana route = unmount poprzedniej strony.

Context — kiedy

Temat globalny (theme, locale, auth user) — unikaj dużych, często zmieniających się obiektów (re-render wszystkich konsumentów). Dane serwerowe → React Query, nie Context.

Część 7 — Wydajność i wzorce

7.1 Kiedy optymalizować

Najpierw zmierz (React DevTools Profiler). Nie owijaj wszystkiego w memo — koszt porównania propsów też istnieje.

NarzędzieKiedy
React.memoDrogi child z tymi samymi props — skip re-render
useMemoKosztowne wyliczenie — cache między renderami
useCallbackStabilna funkcja dla memo child lub dependency effect
Code splittinglazy(() => import('./Page')) — mniejszy initial bundle

7.2 Composition over inheritance

React nie używa dziedziczenia klas — kompozycja (children, render props, custom hooks).

7.3 React 19 — warto znać

  • use — odczyt Promise/Context w renderze (Suspense)
  • Actions — form actions z pending state
  • Ref as prop — bez forwardRef w wielu przypadkach
  • Lepsze batching, dokumentacja hooks-first

Część 8 — Najczęstsze błędy

  1. Mutacja stanu — state.push(x) zamiast setState([...state, x])
  2. Brak key lub key = index — błędne listy po edycji
  3. useEffect do pochodnego stanu — niepotrzebny effect + pętle
  4. Brak dependency array / złe zależności — stale closure, nieskończone pętle
  5. Stan serwera w useState — znika przy unmount; użyj React Query
  6. Prop drilling 10 poziomów — Context lub composition
  7. Context na często zmieniane dane — re-render całego drzewa
  8. Przedwczesna optymalizacja — memo wszędzie bez profilera
  9. Hooks w warunku — łamanie rules of hooks
  10. Brak cleanup w useEffect — memory leak (subskrypcje, timery)

Pytania rekrutacyjne — krótkie odpowiedzi

Junior / Mid

1. Co to jest React?

Biblioteka UI do budowy interfejsów z komponentów — deklaratywny model, SPA.

2. JSX — co to?

Składnia HTML-like w JS — kompiluje się do elementów React.

3. Props vs state?

Props — z rodzica, readonly. State — wewnętrzny, zmieniany setterem.

4. Po co key w liście?

Identyfikacja elementu dla reconciliation — stabilny id, nie index.

5. Co robi useState?

Dodaje lokalny stan komponentu + funkcję do jego aktualizacji.

6. Co robi useEffect?

Efekt uboczny po renderze — sync z API, DOM, subskrypcjami; opcjonalny cleanup.

7. Dependency array w useEffect?

Lista zależności — effect re-run gdy się zmienią; [] = mount; brak = każdy render.

8. Controlled vs uncontrolled input?

Controlled — value w React state. Uncontrolled — wartość w DOM (ref).

9. Co to lifting state up?

Przeniesienie współdzielonego stanu do wspólnego rodzica.

10. Virtual DOM — idea?

Drzewo JS — React diffuje z poprzednim, aktualizuje real DOM minimalnie.

11. Class vs function component?

Function + hooks — standard. Class — legacy (lifecycle methods).

12. Co to custom hook?

Funkcja use* enkapsulująca logikę ze hooks — wielokrotnego użytku.

13. Co robi useRef?

Mutable ref — DOM node lub wartość bez triggerowania re-render.

14. Fragment — po co?

Grupowanie bez dodatkowego węzła DOM.

15. React Router — Outlet?

Miejsce renderowania zagnieżdżonej trasy child.

Mid / Senior

16. Rules of hooks?

Top level only; tylko w komponentach/custom hooks — nie w pętlach/warunkach.

17. Stale closure w useEffect?

Effect „pamięta” stare wartości — naprawa: poprawne deps lub functional update.

18. useMemo vs useCallback?

useMemo — wartość. useCallback — funkcja (memoizowana referencja).

19. Kiedy React.memo?

Gdy child drogi w renderze i dostaje te same props — unikaj ślepo wszędzie.

20. Reconciliation — jak działa?

Porównanie virtual trees; key decyduje o mapowaniu elementów listy.

21. Batching w React 18?

Wiele setState → jeden re-render (sync i async events).

22. Strict Mode — po co double mount?

Dev only — wykrywa brak cleanup i unsafe side effects.

23. Context — wady?

Każda zmiana value re-renderuje wszystkich konsumentów — nie do częstych update.

24. React Query vs Context dla API?

React Query — cache, refetch, stale, dedup. Context — nie do serwerowych danych.

25. Suspense — idea?

Component „wstrzymuje” render do ready (lazy, data) — fallback UI.

26. Error Boundary — co łapie?

Błędy renderu w dzieciach — nie łapie event handlers, async, SSR same.

27. useReducer vs useState?

Reducer — złożone przejścia stanu, wiele akcji, testowalna logika.

28. Code splitting w React?

React.lazy + Suspense — dynamic import, mniejszy initial bundle.

29. SSR vs CSR?

SSR — HTML z serwera, szybszy FCP. CSR — pusty HTML + JS bundle (Vite SPA).

30. React 19 use hook?

Czyta Promise/Context w renderze — integracja ze Suspense.

Pułapki / tricky

31. Czy setState jest synchroniczny?

Nie — aktualizacja asynchroniczna/batch; zaraz po setState stary stan w tej samej funkcji.

32. Czy mutacja props dozwolona?

Nie — antywzorzec; props readonly, single direction data flow.

33. Index jako key — kiedy bug?

Reorder, delete, insert w środku listy — zły DOM reuse, utrata stanu inputów.

34. useEffect([]) w Strict Mode — 2×?

Tak w dev — mount, unmount, mount; test cleanup.

35. Czy useMemo zapobiega re-renderowi?

Nie — tylko cache wartości; re-render nadal następuje.

36. Fetch w useEffect vs React Query?

RQ — cache, dedup, background refetch; useEffect fetch — ręcznie wszystko.

37. Dlaczego stan znika po zmianie route?

Unmount komponentu — lokalny useState ginie; Query cache zostaje.

38. Czy React = framework?

Nie — biblioteka UI; routing/dane to osobne biblioteki.

39. Event pooling (React 17+)?

Usunięte — synthetic event nie jest pooled; można async używać event properties.

40. Najczęstszy błąd początkującego?

Mutacja stanu / brak key / useEffect bez deps lub z błędnymi deps.
