React Query TanStack Query — hooki

Setup (bez hooka — raz w main.tsx)

const queryClient = new QueryClient()

<QueryClientProvider client={queryClient}>
  <RouterProvider router={router} />
</QueryClientProvider>

QueryClient trzyma cache — jeden na całą app. Provider daje dostęp hookom.

Query keys — fundament cache

export const authorKeys = {
  all: ['authors'] as const,
  detail: (id: string) => ['authors', id] as const,
}

Klucz = identyfikator danych w cache. Hierarchia: ['authors'] invaliduje wszystko; ['authors', id] — jeden rekord.

useQuery — odczyt danych

const authorsQuery = useQuery({
  queryKey: authorKeys.all,
  queryFn: () => authorList.getAll(),
})

Co robi: fetch przy mount, cache wynik, refetch wg reguł (focus okna, reconnect, staleTime).

Zwraca (najważniejsze):

PoleZnaczenie
dataDane — undefined dopóki brak sukcesu
isPending / isLoadingPierwsze ładowanie (v5: isPending bez cache)
isFetchingTrwa fetch (także background refetch)
isError, errorBłąd queryFn
refetch()Ręczne odświeżenie
status'pending' | 'error' | 'success'

useMutation — zapis / zmiana

const saveAuthorMutation = useMutation({
  mutationFn: ({ id, input }) =>
    id ? authorList.update(id, input) : authorList.create(input),
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: authorKeys.all })
  },
})

Co robi: nie fetchuje automatycznie — wołasz mutate() / mutateAsync() przy akcji użytkownika.

Zwraca: mutate, mutateAsync, isPending, isError, isSuccess, reset.

invalidateQueries — oznacza cache jako stale → refetch aktywnych query z tym kluczem.

useQueryClient — dostęp do cache

const queryClient = useQueryClient()  // ten sam QueryClient z Provider

queryClient.invalidateQueries({ queryKey: ['authors'] })
queryClient.setQueryData(['authors'], newList)   // optimistic update
queryClient.getQueryData(['authors'])
queryClient.removeQueries({ queryKey: ['authors'] })

Nie tworzy nowego klienta — zwraca referencję z kontekstu.

React Router — hooki i API

Setup — data router (Twój projekt)

export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    children: [
      { index: true, element: <HomePage /> },
      { path: 'authors', element: <AuthorsPage /> },
      { path: '*', element: <NotFoundPage /> },
    ],
  },
])

// main.tsx
<RouterProvider router={router} />

createBrowserRouter — trasy definiujesz poza komponentem; loader/action (opcjonalnie) przed renderem.

Komponenty (nie hooki, ale must know)

KomponentRola
<Outlet />Renderuje aktywną trasę child — w RootLayout
<NavLink>Link z klasą active gdy trasa aktywna
<Link>Nawigacja bez przeładowania strony

useNavigate — nawigacja imperatywna

const navigate = useNavigate()

navigate('/authors')
navigate(-1)                    // wstecz
navigate('/authors', { replace: true })
navigate('/authors', { state: { from: 'home' } })

Po submit formularza, po logowaniu — gdy nie używasz <Link>.

useParams — parametry z URL

// route: authors/:authorId
const { authorId } = useParams()

useQuery({
  queryKey: authorKeys.detail(authorId!),
  queryFn: () => authorList.getById(authorId!),
  enabled: !!authorId,
})

Dynamiczne segmenty trasy — łączenie z React Query przez enabled.

useSearchParams — query string (?page=2)

const [searchParams, setSearchParams] = useSearchParams()
const page = Number(searchParams.get('page') ?? '1')

setSearchParams({ page: '2' })   // ?page=2

Filtry, paginacja, sortowanie w URL — shareable linki.

useLocation — aktualna lokalizacja

const location = useLocation()
// location.pathname  → '/authors'
// location.search    → '?tab=list'
// location.state     → dane z navigate(..., { state })

Scroll restore, breadcrumbs, „skąd przyszedłem”.

useMatch · useResolvedPath

const match = useMatch('/authors/:id')
const resolved = useResolvedPath('../settings')

useMatch — czy trasa pasuje (aktywna sekcja menu). useResolvedPath — relatywna ścieżka względem bieżącej trasy.

useOutletContext — dane z layoutu do child

// RootLayout
<Outlet context={{ user }} />

// Child page
const { user } = useOutletContext<{ user: User }>()

Alternatywa dla prop drilling w zagnieżdżonych trasach — Context też OK.

Mount / unmount a stan

Zmiana trasy / → /authors → AuthorsPage mount. Wyjście = unmount → useState ginie, React Query cache zostaje. Dlatego lista autorów wraca po powrocie bez ponownego „pustego startu”.

React Hook Form — hooki

Filozofia

Minimalne re-rendery — rejestracja pól przez ref (uncontrolled), walidacja na submit / on blur. Zod przez zodResolver — jeden schemat na runtime + TypeScript.

useForm — główny hook

const {
  register,
  handleSubmit,
  reset,
  watch,
  control,
  formState: { errors, isSubmitting, isDirty, isValid },
} = useForm<CreateAuthorInput>({
  defaultValues,
  resolver: zodResolver(createAuthorSchema),
  mode: 'onTouched',           // kiedy walidować
  reValidateMode: 'onChange',  // re-walidacja po błędzie
})
ReturnPo co
register(name)Podpięcie inputa — spread na element
handleSubmit(fn)Submit tylko gdy walidacja OK
reset(values)Reset formularza — np. po zmianie wybranego autora
watch(name?)Obserwuj wartości pól (re-render!)
controlDla Controller — controlled components
formState.errorsBłędy walidacji per pole
setValue / getValuesImperatywny odczyt/zapis pól
 
// AuthorForm — wzorzec z projektu
<form onSubmit={handleSubmit(submitForm)}>
  <input {...register('firstName')} />
  {errors.firstName && <span>{errors.firstName.message}</span>}
</form>

// reset gdy zmienia się wybrany autor (edycja)
useEffect(() => {
  reset(defaultValues)
}, [defaultValues, reset])

Controller + control — controlled / custom UI

<Controller
  name="categoryId"
  control={control}
  render={({ field, fieldState }) => (
    <Select
      value={field.value}
      onChange={field.onChange}
      error={fieldState.error?.message}
    />
  )}
/>

Gdy komponent nie obsługuje natywnego ref — MUI Select, DatePicker, React Select.

useWatch — obserwuj pole bez watch() z useForm

// W child — mniejszy zakres re-render niż watch() w rodzicu
const email = useWatch({ control, name: 'email' })

Izoluje re-render do komponentu, który naprawdę potrzebuje wartości.

useFieldArray — dynamiczna lista pól

const { fields, append, remove } = useFieldArray({
  control,
  name: 'titles',
})

{fields.map((field, index) => (
  <input key={field.id} {...register(`titles.${index}.name`)} />
))}

Wiele tytułów autora, wiersze faktury — append/remove wierszy formularza.

FormProvider + useFormContext

// Rodzic
const methods = useForm(...)
return (
  <FormProvider {...methods}>
    <AuthorFormFields />
  </FormProvider>
)

// Głęboki child — bez prop drilling register/control
const { register, formState: { errors } } = useFormContext<CreateAuthorInput>()

Przepływ w AuthorsPage — wszystko razem

AuthorsPage
│
├─ useAuthors()                    [React Query]
│    ├─ useQuery → lista autorów (cache)
│    └─ useMutation → save + invalidate
│
├─ useState(selectedAuthor)        [React — UI lokalne]
│
└─ AuthorForm                      [Hook Form]
     ├─ useForm + zodResolver
     ├─ reset(defaultValues)      ← sync z selectedAuthor
     └─ onSubmit → saveAuthor()   → mutateAsync → invalidate → refetch listy

Edycja autora: klik w liście → selectedAuthor → nowe defaultValues → reset w formularzu. Nowy autor: „Nowy autor” → selectedAuthor = null → pusty formularz.

Router: /authors renderuje AuthorsPage w Outlet. Query cache przeżywa wyjście na Home i powrót.

Najczęstsze błędy

React Query

  1. Fetch w useEffect zamiast useQuery — brak cache, dedup, refetch
  2. Brak queryKey lub niestabilny key (nowy obiekt co render)
  3. useQueryClient() mylone z new QueryClient() w hooku
  4. Brak invalidateQueries po mutacji — stara lista na ekranie
  5. Cały obiekt w key bez serializacji — cache miss

React Router

  1. Brak Outlet — child route się nie renderuje
  2. NavLink to="/" bez end — aktywny na każdej podstronie
  3. Stan w useState zamiast URL — brak deep linków (useParams / searchParams)
  4. BrowserRouter vs createBrowserRouter — mieszanie API v6 data router

React Hook Form

  1. Brak reset przy zmianie defaultValues — formularz pokazuje stare dane
  2. watch() wszędzie — zbędne re-rendery całego formularza
  3. Custom input bez Controller — wartość poza kontrolą RHF
  4. Duplikacja schematu Zod i typów TS — użyj z.infer
  5. handleSubmit pominięte — submit omija walidację

Pytania rekrutacyjne — krótkie odpowiedzi

Junior / Mid

1. Po co React Query?

Cache, sync i stan serwerowych danych — fetch, refetch, loading/error bez ręcznego useEffect.

2. Co robi useQuery?

Fetch danych po mount, cache pod queryKey, zwraca data/loading/error.

3. Co robi useMutation?

Wykonuje operację zapisu — wołana ręcznie przez mutate/mutateAsync.

4. Co to queryKey?

Identyfikator danych w cache — np. ['authors'].

5. Po co invalidateQueries?

Oznacza cache jako nieaktualny → refetch aktywnych query.

6. useQueryClient tworzy nowy klient?

Nie — zwraca QueryClient z Provider context.

7. Po co React Router?

Mapowanie URL → komponenty w SPA bez przeładowania strony.

8. Co robi Outlet?

Renderuje aktywną zagnieżdżoną trasę child.

9. useNavigate vs Link?

Link — deklaratywnie w JSX. useNavigate — imperatywnie po akcji (submit, timer).

10. Co robi useParams?

Zwraca parametry dynamiczne z URL (:id).

11. Po co React Hook Form?

Formularze z minimalnymi re-renderami i prostą walidacją.

12. Co zwraca useForm?

register, handleSubmit, reset, control, formState (errors), watch…

13. Co robi register('field')?

Podpina input do formularza — ref + onChange/onBlur.

14. Po co handleSubmit?

Submit tylko po przejściu walidacji resolvera.

15. zodResolver — po co?

Łączy schemat Zod z RHF — walidacja runtime + typy TS.

Mid / Senior

16. staleTime vs gcTime?

staleTime — świeżość bez refetch. gcTime — jak długo trzymać w cache po unmount.

17. Optimistic update w React Query?

onMutate → setQueryData z nową wartością → rollback w onError.

18. enabled: false w useQuery?

Nie fetchuj dopóki warunek false — np. brak authorId z useParams.

19. Dlaczego lista wraca po powrocie na route?

React Query cache — dane poza useState komponentu.

20. createBrowserRouter vs BrowserRouter?

Data router — trasy + loadery/actions, lepsze dla RR v6.4+.

21. useSearchParams — case?

Filtry/paginacja w URL — shareable, back/forward działa.

22. register vs Controller?

register — native inputs, mało re-renderów. Controller — custom controlled UI.

23. Po co reset(defaultValues) w useEffect?

RHF nie aktualizuje pól gdy props się zmienią — reset synchronizuje edycję.

24. watch vs useWatch?

watch z useForm — re-render rodzica. useWatch — izolowany re-render w child.

25. FormProvider + useFormContext?

Udostępnia metody formularza głębokim dzieciom bez prop drilling.

26. Query key factory pattern?

authorKeys.all, authorKeys.detail(id) — spójna invalidacja hierarchii.

27. mutate vs mutateAsync?

mutate — fire-and-forget. mutateAsync — Promise, await w handlerze (Twój saveAuthor).

28. isPending vs isFetching?

isPending — brak danych jeszcze. isFetching — trwa request (także background).

29. Loader w React Router + useQuery?

Loader prefetch przed renderem LUB useQuery w komponencie — nie duplikuj bez potrzeby.

30. mode onTouched w RHF?

Walidacja po pierwszym blur pola, potem onChange — balans UX/wydajność.

Pułapki / tricky

31. useEffect + fetch vs useQuery?

useEffect — brak cache/dedup. useQuery — standard na dane serwerowe.

32. QueryClient w komponencie?

new QueryClient() w renderze = utrata cache co render — tylko w main.tsx.

33. NavLink / bez end na home?

Home aktywny na wszystkich podstronach — dodaj end na index link.

34. defaultValues vs reset przy edycji?

defaultValues tylko przy pierwszym mount — zmiana wymaga reset().

35. Czy RHF to controlled?

Domyślnie uncontrolled (ref) — mniej re-renderów niż useState per field.

36. invalidateQueries vs refetchQueries?

invalidate — stale + refetch jeśli aktywny. refetch — wymusza od razu.

37. Strict Mode a useQuery?

Dev double mount — 2 fetchy bez dedup; w prod raz. Opcja retry/staleTime łagodzi dev.

38. useFieldArray — key?

field.id z RHF — nie index (jak w React lists).

39. Gdzie trzymać selectedAuthor?

UI lokalne — useState OK. Gdy deep link do edycji — id w URL + useParams.

40. Trzy biblioteki — kto za co?

Router = która strona. Query = dane serwerowe. RHF = stan formularza.
