Część 0 — Fundamenty

Spring Boot 4 stoi na Spring Framework 7. To pierwsza duża para od Boot 3 / Framework 6 (2022). Pakiety jakarta.* z migracji 2→3 zostają — EE 11 podnosi wersje API, nie zmienia namespace.

Pułapka: Java 17 nadal wystarczy do startu. Virtual threads, Class-File API i pełny zysk z 7/4 wymagają 21+ (25 LTS w 2026).

1. Framework 7 — co pęka

Większość usunięć to API oznaczone do wycięcia od 6.0. Dwie rzeczy gryzą cicho.

javax.annotation / javax.inject — usunięte, nie deprecated

Mostek z 6.x zniknął. @javax.annotation.PostConstruct nadal się kompiluje (jar na classpath), ale Spring 7 go nie widzi — init nie odpala, bez wyjątku. Grep: javax.annotation, javax.inject → jakarta.*.

Proxy: CGLIB jest konsekwentnym defaultem także dla @Async. Per bean: @Proxyable(INTERFACES) albo @Proxyable(TARGET_CLASS).

Testy JUnit Jupiter: SpringExtension ma scope per metoda. Jeśli @Nested pada po upgrade — @SpringExtensionConfig(useTestClassScopedExtensionContext = true) albo property spring.test.extension.context.scope=test_class.

2. Framework 7 — nowości, które warto znać

Resilience w spring-core

Spring Retry jako osobny projekt schodzi ze sceny. W 7 jest RetryTemplate + @Retryable + @ConcurrencyLimit, włączane przez @EnableResilientMethods. Metody reactive dostają retry Reactor; imperatywne — RetryTemplate.

@Configuration
@EnableResilientMethods
class ResilienceConfig {}

@Retryable(maxAttempts = 3)
public Order load(String id) { ... }

@ConcurrencyLimit(4)
public void process(Job job) { ... }
BeanRegistrar

Gdy @Bean w @Configuration nie wystarcza (wiele rejestracji, logika, konkretny typ). Programatyczna rejestracja zamiast „kilku beanów w jednej metodzie”.

JSpecify zamiast JSR 305

org.springframework.lang.Nullable deprecated. Pakiet: org.jspecify.annotations. Kotlin i null-checkery mogą zacząć sypać błędami — to zmiana semantyki, nie tylko importu.

  • JmsClient — fluent API jak JdbcClient/RestClient; domyślny SimpleDestinationResolver cache’uje Queue/Topic.
  • JPA 3.2: EntityManager / EntityManagerFactory przez @Autowired; Hibernate StatelessSession (lepiej 7.2).
  • Class-File API (Java 24+) zamiast forka ASM przy czytaniu bytecode — przezroczyste.
  • RestTestClient — nie-reaktywny brat WebTestClient.
  • Test context może być pauzowany, gdy nie jest używany (tło nie tyka CPU między klasami).

3. HTTP: RestClient, interfejsy, wersjonowanie API

RestTemplate jest „feature complete” od lat; w 7.0 deprecated w dokumentacji, w 7.1 @Deprecated, usunięcie planowane na Framework 8. Kierunek: RestClient (imperatywny) albo HTTP Interface Client.

// Deklaratywny klient
@HttpExchange(url = "https://api.example.com")
interface OrderClient {
  @GetExchange("/orders/{id}")
  Order get(@PathVariable String id);
}

@Configuration
@ImportHttpServices(group = "orders", types = OrderClient.class)
class HttpClientsConfig {}

Wersjonowanie API jest first-class w MVC i WebFlux: resolver (nagłówek, path, media type), deprecacja wersji, to samo po stronie RestClient/WebClient. W Boot 4: spring.mvc.apiversion.* / spring.webflux.apiversion.*.

PathPattern zastępuje AntPathMatcher (deprecated w MVC). W 7.0 działa wreszcie leading /**/, np. /**/pages/index.html.

@Configuration
class WebConfig implements WebMvcConfigurer {
  @Override
  public void configureMessageConverters(
      HttpMessageConverters.ServerBuilder builder) {
    builder.jsonMessageConverter(
        new JacksonJsonHttpMessageConverter(JsonMapper.builder().build()));
  }
}

4. Boot 4 — modularizacja starterów

To największa zmiana strukturalna Boot 4. Jeden gruby spring-boot-autoconfigure rozpadł się na małe moduły. Starter = technologia; każdy ma companion -test.

spring-boot-starter-webspring-boot-starter-webmvc (stara nazwa deprecated)

spring-boot-starter-aopspring-boot-starter-aspectj
spring-boot-starter-oauth2-*spring-boot-starter-security-oauth2-*
spring-boot-starter-batch + JDBC autoin-memory default; JDBC → -batch-jdbc

Szybki most: spring-boot-starter-classic + spring-boot-starter-test-classic — cały classpath jak w 3.x. Potem zdejmujesz classic i dobierasz konkretne startery. Oficjalna rekomendacja: nie zostawać na classic.

Usunięte w 4.0: Undertow, Pulsar Reactive, skrypty „fully executable jar” (Unix), integracja Spock (Groovy 5), bezpośredni Spring Session Hazelcast/MongoDB (zespoły vendorów).

5. Boot 4 — Jackson 3, testy, właściwości

Jackson 3

Pakiet runtime: com.fasterxml.jackson → tools.jackson. Adnotacje (@JsonIgnore, @JsonView) zostają w com.fasterxml.jackson.annotation.

Boot 3 / Jackson 2Boot 4 / Jackson 3
ObjectMapperJsonMapper (XML: XmlMapper)
Jackson2ObjectMapperBuilderCustomizerJsonMapperBuilderCustomizer
@JsonComponent / @JsonMixin@JacksonComponent / @JacksonMixin
spring.jackson.read.*spring.jackson.json.read.*
JsonProcessingException extends IOExceptionJacksonException extends RuntimeException

Bean ObjectMapper nie nadpisuje już auto-configu — musisz zdefiniować JsonMapper. Tymczasowo: spring.jackson.use-jackson2-defaults=true albo deprecated moduł spring-boot-jackson2.

Jackson 3 rejestruje wszystkie moduły z classpath (w 3.x tylko „well-known”). Wyłączenie: spring.jackson.find-and-add-modules=false.

Testy

@SpringBootTest
@AutoConfigureMockMvc   // bez tego nie ma MockMvc
class OrderApiTest {
  @MockitoBean           // nie @MockBean — usunięte
  OrderService orders;
}
  • @MockBean / @SpyBean → @MockitoBean / @MockitoSpyBean. Nowe adnotacje nie działają w @Configuration — współdzielone mocki przez @MockitoBean(types=…) na klasie testu albo własną meta-adnotację.
  • TestRestTemplate: extra spring-boot-resttestclient + @AutoConfigureTestRestTemplate. Lepszy kierunek: RestTestClient + @AutoConfigureRestTestClient.
  • @Mock / @Captor: listener Boota usunięty — użyj MockitoExtension.

Inne defaulty Boot 4

  • Proby liveness/readiness włączone (management.endpoint.health.probes.enabled).
  • DevTools Live Reload wyłączony (spring.devtools.livereload.enabled=true).
  • Mongo: część properties z spring.data.mongodb → spring.mongodb; UUID/BigDecimal bez defaultu — ustaw jawnie.
  • management.tracing.enabled → management.tracing.export.enabled.
  • Nowy starter: spring-boot-starter-opentelemetry.

6. Ścieżka migracji

  1. Wejdź na ostatnie Boot 3.5.x. Wyczyść każde deprecation — w 4.0 te API są wycięte, nie ostrzegane.
  2. Java 17+ w CI (cel: 21 lub 25). Kotlin ≥ 2.2. GraalVM native: 25+.
  3. Zamień Undertow → Tomcat/Jetty. Grep javax.annotation / javax.inject.
  4. Podnieś parent/BOM do 4.0.x. Dodaj runtime spring-boot-properties-migrator (usuń po poprawkach yamla).
  5. Opcjonalnie classic startery, żeby aplikacja wstała; potem konkretne startery + -test.
  6. Jackson: najpierw use-jackson2-defaults=true, potem JsonMapper i catch na JacksonException.
  7. Testy: @MockitoBean, @AutoConfigureMockMvc, startery -test per technologia.
  8. Batch: jeśli metadata w DB — spring-boot-starter-batch-jdbc.
<!-- Maven: migrator properties (runtime, potem wywalić) -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-properties-migrator</artifactId>
  <scope>runtime</scope>
</dependency>

Portfolio idzie razem: Security 7, Kafka 4, REST Docs 4, Pulsar 2. Sprawdź release notes bibliotek poza BOM (Spring Cloud).

Typowe błędy

  1. Skok z Boot 3.3 prosto na 4.0 — bez 3.5 deprecation warnings zamieniają się w błędy kompilacji bez podpowiedzi.
  2. @PostConstruct z javax.* — kompiluje się, init nigdy nie wstaje.
  3. Undertow w Dockerze / starterze — Boot 4 go nie ma; war na starym Tomcacie też nie spełni Servlet 6.1.
  4. Zostawienie samego Flyway/Liquibase jar — auto-config nie wstanie bez spring-boot-starter-flyway / -liquibase.
  5. Bean ObjectMapper „nadpisuje Jacksona” — w 4.x trzeba JsonMapper.
  6. catch (IOException) na JSON — JacksonException jest runtime; błąd serializacji ucieka nieobsłużony.
  7. @MockBean w @TestConfiguration — usunięte; nowe adnotacje nie działają na klasach konfiguracji.
  8. @SpringBootTest + wstrzyknięty MockMvc — bez @AutoConfigureMockMvc beana nie ma.
  9. Spring Batch po upgrade „gubi” historię jobów — default jest in-memory; wróć przez -batch-jdbc.
  10. Classic starter na stałe — działa, ale traci sens modularizacji i puchnie native image / classpath.
