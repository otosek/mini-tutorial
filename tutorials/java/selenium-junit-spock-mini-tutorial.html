Selenium WebDriver

Co robi

API do interakcji z przeglądarką jak użytkownik — klik, wpisywanie, odczyt DOM. WebDriver 4 — standard W3C. Sterowniki: Chrome (ChromeDriver), Firefox (GeckoDriver), Edge.

Minimalny test

WebDriver driver = new ChromeDriver();
driver.get("https://app.example.com/authors");
driver.findElement(By.id("firstName")).sendKeys("Anna");
driver.findElement(By.cssSelector("button[type=submit]")).click();
assertTrue(driver.getPageSource().contains("Anna"));
driver.quit();

Lokalizatory — kolejność preferencji

LocatorPrzykładUwagi
By.idBy.id("email")Najstabilniejszy jeśli unikalny
data-testid[data-testid=save-author]Celowo pod testy — best practice
By.cssSelectorbutton.primaryElastyczny, preferowany nad XPath
By.xpath//button[text()='Zapisz']Potężny, kruchy przy zmianach DOM

Explicit wait — nie Thread.sleep

WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));

WebElement btn = wait.until(
    ExpectedConditions.elementToBeClickable(By.cssSelector("[data-testid=save]"))
);

Implicit wait — globalny timeout findElement (rzadko + explicit). Fluent wait — polling z ignorowaniem wyjątków. Thread.sleep — ❌ flaky, wolne.

Page Object Model (POM)

public class AuthorsPage {
    private final WebDriver driver;
    private final WebDriverWait wait;

    public AuthorsPage(WebDriver driver) {
        this.driver = driver;
        this.wait = new WebDriverWait(driver, Duration.ofSeconds(10));
    }

    public void open() {
        driver.get("http://localhost:5173/authors");
    }

    public void fillFirstName(String name) {
        wait.until(ExpectedConditions.visibilityOfElementLocated(By.name("firstName")))
            .sendKeys(name);
    }

    public void clickSave() {
        wait.until(ExpectedConditions.elementToBeClickable(By.cssSelector("button[type=submit]")))
            .click();
    }
}

Test nie zna selektorów — tylko metody strony. Zmiana UI = jedna klasa do poprawy.

Selenium + JUnit — wzorzec

@ExtendWith(/* opcjonalnie: Selenium-Jupiter */)
class AuthorsE2ETest {

    static WebDriver driver;

    @BeforeAll
    static void setupClass() {
        driver = new ChromeDriver();
        driver.manage().window().maximize();
    }

    @AfterAll
    static void tearDownClass() {
        if (driver != null) driver.quit();
    }

    @BeforeEach
    void openAuthorsPage() {
        driver.get("http://localhost:5173/authors");
    }

    @Test
    @DisplayName("Dodanie autora — widoczny na liście")
    void shouldAddAuthor() {
        var page = new AuthorsPage(driver);
        page.fillFirstName("Jan");
        page.fillLastName("Kowalski");
        page.fillEmail("jan@example.com");
        page.clickSave();

        assertTrue(page.listContains("Jan Kowalski"));
    }
}

Spock

Co to jest

Framework testowy na JVM w Groovy — składnia BDD: given / when / then. Działa z Maven/Gradle obok Javy. Mocking wbudowany (Mock(), Stub()).

Specification — struktura

class AuthorServiceSpec extends Specification {

    def "should create author with valid input"() {
        given: "empty repository"
        def repo = Mock(AuthorRepository)
        def service = new AuthorService(repo)

        when: "creating author"
        def result = service.create("Anna", "Nowak", "a@example.com")

        then: "saved once"
        1 * repo.save({ it.firstName == "Anna" })
        result.email == "a@example.com"
    }
}

given — setup. when — akcja. then — asercje + interakcje mock (1 * = dokładnie jedno wywołanie).

Data table — parameterized w Spock

def "email validation"(String email, boolean valid) {
    expect:
    validator.isValid(email) == valid

    where:
    email              | valid
    "jan@example.com"  | true
    "bad"              | false
    ""                 | false
}

Spock + Selenium

class AuthorsPageSpec extends Specification {

    WebDriver driver

    def setup() {          // = @Before
        driver = new ChromeDriver()
    }

    def cleanup() {        // = @After
        driver?.quit()
    }

    def "add author via UI"() {
        given:
        def page = new AuthorsPage(driver)
        page.open()

        when:
        page.fillFirstName("Ewa")
        page.clickSave()

        then:
        page.listContains("Ewa")
    }
}

Najczęstsze błędy

  1. Thread.sleep zamiast explicit wait — flaky testy
  2. Selektory kruche — XPath po indeksie, klasy CSS generowane
  3. Brak quit()/close() — zombie procesy ChromeDriver w CI
  4. Testy zależne od kolejności — współdzielony stan bez @BeforeEach reset
  5. Logika w teście zamiast POM — duplikacja selektorów
  6. E2E na unit pipeline — wolne; tag @Tag("e2e") osobno
  7. Spock then: z przypisaniem — tylko asercje i mock interactions
  8. JUnit @BeforeAll non-static z instancją driver — błąd lifecycle
  9. Testowanie prod — osobne env, dane testowe, idempotentność
  10. Brak screenshot on failure — trudny debug w CI

Pytania rekrutacyjne — krótkie odpowiedzi

Junior / Mid

1. Co robi Selenium WebDriver?

Automatyzuje przeglądarkę — symuluje akcje użytkownika na UI.

2. JUnit 5 vs JUnit 4?

JUnit 5 (Jupiter) — nowe adnotacje, extensions, parameterized; pakiet jupiter.api.

3. Co to Spock?

Framework testowy Groovy — BDD given/when/then na JVM.

4. @BeforeEach vs @BeforeAll?

BeforeEach — przed każdym testem. BeforeAll — raz przed klasą (static).

5. Explicit vs implicit wait?

Explicit — warunek na element (WebDriverWait). Implicit — globalny timeout findElement.

6. Dlaczego nie Thread.sleep?

Flaky — za krótko = fail, za długo = wolne CI.

7. Co to Page Object Model?

Klasa na stronę UI — enkapsuluje selektory i akcje.

8. Preferowany locator?

id, data-testid, cssSelector — unikaj kruchego XPath.

9. given/when/then w Spock?

Setup / akcja / asercje — bloki BDD w Specification.

10. Spock Mock() — co robi?

Mock obiektu — weryfikacja interakcji w then (np. 1 * repo.save()).

11. @ParameterizedTest w JUnit?

Jeden test, wiele zestawów danych — @CsvSource, @MethodSource.

12. driver.quit() vs close()?

quit — zamyka sesję i wszystkie okna. close — bieżące okno.

13. Headless Chrome — po co?

CI bez GUI — szybsze, stabilne pipeline.

14. AssertJ vs JUnit assert?

AssertJ — fluent, czytelne łańcuchy (hasSize, extracting).

15. where: w Spock?

Tabela danych — data-driven test bez osobnej adnotacji.

Mid / Senior

16. Selenium Grid?

Hub + nodes — równoległe testy na wielu browser/OS.

17. JUnit 5 Extensions?

Mechanizm rozszerzeń — @ExtendWith, callbacki, DI (Selenium-Jupiter).

18. @TestInstance(Lifecycle.PER_CLASS)?

Jedna instancja klasy testowej — współdzielony stan między testami.

19. Flaky test — jak naprawić?

Explicit waits, stabilne selektory, izolacja danych, retry tylko jako tymczas.

20. Spock @Unroll?

Każdy wiersz where = osobny raport testu z parametrami w nazwie.

21. Spock Stub vs Mock?

Stub — zwraca wartości. Mock — weryfikuje wywołania w then.

22. Page Factory (@FindBy)?

Selenium wzorzec — lazy init elementów; dziś często prostsze POM ręczne.

23. E2E vs integration vs unit?

Unit — jedna klasa. Integration — kilka warstw. E2E — pełny UI + backend.

24. @Tag e2e — po co?

Separacja szybkich unit od wolnych E2E w pipeline.

25. WebDriverManager?

Biblioteka — auto-pobiera matching ChromeDriver/GeckoDriver.

26. Selenium 4 relative locators?

above, below, leftOf, rightOf — lokalizacja względem innego elementu.

27. Testcontainers + Selenium?

Docker container z browserem — powtarzalne CI bez lokalnego Chrome.

28. Spock withBlocks?

with { } — Groovy spread operator na mock/stub setup.

29. Mockito vs Spock mocks?

Mockito — Java standard. Spock — DSL w Groovy, interakcje w then.

30. Screenshot on failure w JUnit?

TestWatcher extension / @AfterEach — zapis PNG gdy test failed.

Pułapki / tricky

31. Czy Selenium testuje API?

Nie — UI. API → RestAssured, WebTestClient, HttpClient.

32. StaleElementReferenceException?

Element zniknął z DOM (re-render) — ponowne find + wait.

33. Czy Spock wymaga Groovy w prod?

Nie — tylko test scope; prod zostaje Java.

34. @BeforeAll static — dlaczego?

JUnit tworzy instancję per test — static dla wspólnego drogiego setup (driver).

35. then: z println w Spock?

then tylko asercje/mock — side effect w when lub given.

36. Parallel test execution?

JUnit 5 parallel — ostrożnie z Selenium (osobny driver per test).

37. Cypress/Playwright vs Selenium?

Nowsze, auto-wait, JS-native — Selenium nadal standard Java enterprise.

38. Czy POM musi być 1:1 ze stroną?

Nie — komponenty (AuthorFormComponent) + page — composable POM.

39. @Disabled vs @Tag ignore?

Disabled — wyłączony zawsze. Tag — filtrowanie w Maven/Gradle.

40. Najważniejszy wzorzec E2E Java?

Selenium + JUnit + Page Object + explicit wait + tag e2e w CI.
