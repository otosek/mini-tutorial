Część 0 — Fundamenty

OpenFeign to deklaratywny klient HTTP dla Javy: interfejs z adnotacjami Spring MVC (@GetMapping, @PathVariable) → implementacja generowana w runtime (JDK proxy). Spring Cloud OpenFeign dodaje integrację ze Spring Cloud LoadBalancer, OAuth2, Resilience4j i konfiguracją przez properties.

Feign ≠ gateway

Feign to klient wychodzący z serwisu A do serwisu B. Spring Cloud Gateway to wejście z internetu do klastra. Oba mogą współistnieć: SPA → Gateway → Order → Feign → Author.

Starter: spring-cloud-starter-openfeign. Włączenie: @EnableFeignClients na klasie konfiguracji lub @SpringBootApplication.

2. Interfejs i konfiguracja

@FeignClient(name = "author-service", path = "/authors")
public interface AuthorClient {

  @GetMapping("/{id}")
  AuthorDto getById(@PathVariable("id") Long id);

  @PostMapping
  AuthorDto create(@RequestBody CreateAuthorRequest req);

  @GetMapping(params = "name")
  List<AuthorDto> search(@RequestParam("name") String name);
}

name — identyfikator dla LoadBalancer / discovery (nie musi być hostname). url — statyczny URL (pomija LB): url = "http://localhost:8082". path — prefix do wszystkich metod.

Konfiguracja globalna i per-klient:

spring:
  cloud:
    openfeign:
      client:
        config:
          default:
            connectTimeout: 2000
            readTimeout: 5000
            loggerLevel: basic
          author-service:
            readTimeout: 10000

Logowanie: logging.level.com.ex.client.AuthorClient=DEBUG + loggerLevel: full — w prod ostrożnie (body z PII).

Mapowanie odpowiedzi

Feign domyślnie używa tego samego konwertera co Spring MVC (Jackson). ResponseEntity<T> — dostęp do statusu i nagłówków. Błędy 4xx/5xx → FeignException (chyba że własny ErrorDecoder).

@GetMapping("/{id}")
ResponseEntity<AuthorDto> getById(@PathVariable Long id);

3. LoadBalancer i service discovery

name = "author-service" + brak url → Feign woła przez LoadBalancerClient (lb://author-service). Wymaga spring-cloud-starter-loadbalancer (tranzytywnie ze starterem OpenFeign) i rejestru instancji (Eureka, Consul, Kubernetes).

@FeignClient(name = "author-service")
// równoważne żądaniu: GET http://author-service/authors/1
// LoadBalancer wybiera instancję z listy
ŚrodowiskoŹródło listy instancji
Eureka / ConsulRejestracja serwisów przy starcie
Kubernetesspring-cloud-kubernetes-client — Service name = name w Feign
Test / localurl = "http://localhost:8082" albo spring.cloud.discovery.client.simple.instances
Pułapka: name musi zgadzać się z nazwą w discovery. author-service vs authorService — 503 „No instances available”.

4. Interceptory — auth, tenant, tracing

RequestInterceptor — bean dodawany do każdego żądania Feign (lub per-klient przez configuration w @FeignClient).

@Component
public class FeignAuthInterceptor implements RequestInterceptor {
  @Override
  public void apply(RequestTemplate template) {
  // propagacja JWT z bieżącego żądania HTTP (servlet)
    ServletRequestAttributes attrs =
        (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
    if (attrs != null) {
      String auth = attrs.getRequest().getHeader(HttpHeaders.AUTHORIZATION);
      if (auth != null) template.header(HttpHeaders.AUTHORIZATION, auth);
    }
  }
}

Multi-tenancy — doklej X-Tenant-Id z kontekstu (nie z requestu klienta):

template.header("X-Tenant-Id", TenantContext.getCurrentTenant());

OAuth2 client credentials (serwis woła serwis bez użytkownika): spring-cloud-starter-oauth2 + OAuth2AuthorizedClientManager w interceptorze — token z client credentials flow.

RequestContextHolder w @Async

Interceptor oparty na RequestContextHolder nie zadziała w wątku asynchronicznym — kontekst HTTP nie jest przenoszony. Przekaż token/tenant jawnie albo użyj DelegatingSecurityContextRunnable.

5. Fallback, ErrorDecoder, Resilience4j

Fallback (legacy)

@FeignClient(name = "author-service", fallback = AuthorClientFallback.class)
public interface AuthorClient { ... }

@Component
class AuthorClientFallback implements AuthorClient {
  @Override public AuthorDto getById(Long id) {
    return new AuthorDto(id, "Unknown");
  }
}

Fallback wymaga włączenia feign.circuitbreaker.enabled=true (Spring Cloud Circuit Breaker). Nowszy kierunek: Resilience4j bezpośrednio albo HTTP Interface + adnotacje.

ErrorDecoder

@Bean
ErrorDecoder authorErrorDecoder() {
  return (methodKey, response) -> {
    if (response.status() == 404) return new AuthorNotFoundException();
    return new Default().decode(methodKey, response);
  };
}

Resilience4j z Feign

Spring Cloud Circuit Breaker opakowuje Feign — nazwa instancji = name klienta. Konfiguracja jak w tutorialu Resilience4j (resilience4j.circuitbreaker.instances.author-service). Retry na Feign — ostrożnie z POST; lepiej na poziomie biznesu lub tylko GET.

Timeouty: connectTimeout / readTimeout w YAML Feign to pierwsza linia obrony. Nie zastępują circuit breakera przy masowych awariach downstream.

Typowe błędy

  1. Brak @EnableFeignClients. Bean interfejsu nie powstaje — NoSuchBeanDefinitionException.
  2. name bez działającego discovery. „Load balancer does not contain an instance” — dodaj url na local albo rejestrację w Eureka/K8s.
  3. Duplikat @RequestMapping na interfejsie i metodzie. Złe ścieżki — 404. Trzymaj konwencję: path na klasie, metody krótkie.
  4. Feign w tym samym pakiecie co encje JPA. Skanowanie myli konteksty — osobny pakiet ...client.
  5. Interceptor z RequestContextHolder w jobie / @Async. Brak nagłówka Authorization w wywołaniu — 401 na downstream.
  6. Fallback bez włączonego circuit breaker. Klasa fallback nigdy nie jest używana — mylące przy awarii.
  7. Log full na prod. Body requestów z hasłami i tokenami w logach centralnych.
  8. Retry Feign na POST create. Podwójne zamówienie / duplikat rekordu.
  9. Dwa klienty do tego samego serwisu z różnymi timeoutami bez contextId. Konflikt beanów — użyj @FeignClient(contextId = "authorClientV2", ...).
  10. Feign zamiast SDK zewnętrznego API. Brak obsługi paginacji vendor-specific, rate limitów i wersji API — użyj oficjalnego klienta.
