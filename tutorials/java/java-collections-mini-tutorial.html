Część 1 — Fundamenty i hierarchia

1.1 Co to jest Java Collections Framework

Collections Framework to zestaw interfejsów i gotowych implementacji do przechowywania grup obiektów. Zamiast pisać własne tablice z ręcznym resize, używasz List, Set, Map lub Queue — z przewidywalnym API i złożonością operacji.

1.2 Hierarchia (skrót)

Iterable
 └── Collection
      ├── List        (kolejność, duplikaty OK)
      ├── Set         (unikalne elementy)
      └── Queue / Deque

Map — osobna gałąź (klucz → wartość, nie dziedziczy Collection)

Zasada: programuj na interfejsie (List<Order>), twórz konkretną implementację (new ArrayList<>()). Ułatwia testy (mock), zamianę implementacji i czytelność kodu.

1.3 equals, hashCode i kontrakty

HashMap i HashSet opierają się na hashCode() (kubełek) i equals() (porównanie w kubełku). Jeśli dwa obiekty są równe (equals = true), muszą mieć ten sam hashCode. Odwrotnie nie musi być prawda — kolizje hash są normalne.

Pułapka: mutowalny obiekt jako klucz w HashMap — po zmianie pola używanego w hashCode klucz „ginie” w mapie.

Część 2 — Listy: ArrayList vs LinkedList

2.1 ArrayList — tablica dynamiczna

Wewnętrznie: tablica Object[] elementData. Gdy brakuje miejsca — alokacja nowej, większej tablicy i kopiowanie (zwykle ×1,5 rozmiaru). Elementy leżą obok siebie w pamięci — szybki dostęp po indeksie.

// uproszczony model ArrayList
Object[] data = new Object[10];
// get(i)     → data[i]                    O(1)
// add(end)   → data[size++]               O(1) amortyzowane
// add(0, x)  → przesuń wszystko w prawo   O(n)
// remove(i)  → przesuń elementy w lewo     O(n)
ArrayList — kiedy w biznesie
  • Domyślna lista — 99% przypadków (List.of(), wyniki z repozytorium, DTO)
  • Częsty odczyt po indeksie: paginacja, items.get(page * size)
  • Iteracja sekwencyjna po dużej liście zamówień, faktur, logów
  • Dodawanie na końcu listy (append) — np. zbieranie wyników w pętli

2.2 LinkedList — lista dwukierunkowa

Wewnętrznie: łańcuch węzłów (Node). Każdy węzeł ma trzy pola: prev (wskaźnik na poprzedni), next (wskaźnik na następny) i item (dane). Brak ciągłej tablicy — dostęp po indeksie wymaga przejścia od początku lub końca.

// uproszczony model LinkedList
static class Node {
    Node prev;   // ← wskaźnik na poprzedni element
    Node next;   // → wskaźnik na następny element
    Object item;
}
// get(i)           → przejdź i kroków od head/tail   O(n)
// addFirst/Last    → podłącz węzeł                    O(1)
// removeFirst/Last → odłącz węzeł                      O(1)
// add(i, x)        → znajdź pozycję + wstaw           O(n)
LinkedList — kiedy w biznesie
  • Rzadko jako „zwykła lista” — ArrayList jest szybszy przez cache CPU (lokalność pamięci)
  • Implementacja Deque — kolejka FIFO po obu stronach (starszy kod)
  • Scenariusze z częstym dodawaniem/usuwaniem na początku i znanym małym rozmiarem
  • W nowym kodzie: zamiast LinkedList jako listy → ArrayDeque jako kolejka

2.4 Inne listy (krótko)

  • Vector — zsynchronizowany ArrayList; legacy, nie używaj w nowym kodzie
  • CopyOnWriteArrayList — kopia przy każdym zapisie; czytania bez blokady (listenery, snapshot konfiguracji)
  • Collections.synchronizedList() — opakowanie; lepsze: CopyOnWriteArrayList lub struktury z java.util.concurrent

Część 3 — Mapy: HashMap, LinkedHashMap, TreeMap

3.1 HashMap — tablica kubełków + lista/drzewo

Klucz → hashCode() → indeks kubełka. W kubełku: lista (Java 7) lub lista/drzewo (Java 8+, gdy >8 elementów w kubełku). Średnio O(1) dla get/put.

// model logiczny
bucket[index] → Node(key, value, next) → Node → ...
// od Java 8: przy wielu kolizjach → drzewo binarne w kubełku
HashMap — kiedy w biznesie
  • Lookup po ID: Map<Long, Customer>, cache w pamięci
  • Grupowanie: ordersByStatus.computeIfAbsent(status, k -> new ArrayList<>())
  • Liczniki, agregaty: merge(), compute()
  • Indeks pomocniczy z listy encji przed zapisem batch

3.2 LinkedHashMap — HashMap + lista dwukierunkowa

Ta sama struktura co HashMap, plus łańcuch węzłów w kolejności wstawiania (lub dostępu — tryb accessOrder). Iteracja w przewidywalnej kolejności.

LinkedHashMap — kiedy w biznesie
  • Prosty LRU cache — nadpisz removeEldestEntry()
  • Kolejność wyświetlania zgodna z dodaniem (formularz, kreator kroków)
  • Debug — „w jakiej kolejności co wpadło do mapy”
Map<String, Product> lru = new LinkedHashMap<>(16, 0.75f, true) {
    @Override protected boolean removeEldestEntry(Map.Entry<String, Product> e) {
        return size() > 1000;
    }
};

3.3 TreeMap — czerwono-czarne drzewo (Red-Black Tree)

Klucze posortowane naturalnie (Comparable) lub przez Comparator. get/put/remove — O(log n). Brak kubełków hash — porównania kluczy.

TreeMap — kiedy w biznesie
  • Raporty po dacie/kluczu: TreeMap<LocalDate, BigDecimal>
  • firstKey(), lastKey(), subMap(from, to) — zakresy czasowe
  • Kolejka priorytetowa po kluczu (rzadziej niż PriorityQueue)

Część 4 — Zbiory: HashSet, LinkedHashSet, TreeSet

4.1 Implementacja przez mapę

HashSet to HashMap z pustymi wartościami — element = klucz. add(x) = map.put(x, PRESENT). Dlatego kontrakt equals/hashCode jest krytyczny.

4.2 Kiedy który Set

SetWłaściwośćBiznes
HashSetO(1) śr., brak kolejnościUnikalne ID już przetworzonych eventów, deduplikacja
LinkedHashSetO(1) + kolejność wstawianiaUnikalne, ale zachowaj kolejność pierwszego wystąpienia
TreeSetposortowanyTop N unikalnych wartości, harmonogram po czasie
 
Set<String> seen = new HashSet<>();
for (Event e : events) {
    if (!seen.add(e.getId())) continue; // duplikat — pomiń
    process(e);
}

Część 5 — Kolejki, stosy, Deque

5.1 ArrayDeque — tablica cykliczna

Dwa wskaźniki head i tail na tablicy — O(1) addFirst/addLast/poll. Szybszy i lżejszy niż LinkedList jako kolejka.

5.2 PriorityQueue — kopiec (min-heap)

Element z najwyższym priorytetem (najmniejszy wg Comparable lub Comparator) na wierzchu. poll() — O(log n). Nie jest posortowana w całości — tylko korzeń gwarantowany.

Kolejki w biznesie
  • ArrayDeque — BFS, undo/redo, stos (push/pop), kolejka zadań w jednym wątku
  • PriorityQueue — najbliższy termin, najtańsza oferta, scheduler zadań
  • BlockingQueue (ArrayBlockingQueue, LinkedBlockingQueue) — producer/consumer między wątkami
  • Nie używaj Stack (legacy) — użyj ArrayDeque
Queue<Task> urgent = new PriorityQueue<>(
    Comparator.comparing(Task::getDeadline));
urgent.offer(task);
Task next = urgent.poll(); // najwcześniejszy deadline

6.2 Immutable collections (Java 9+)

List.of(), Set.of(), Map.of() — niemutowalne, kompaktowe, bezpieczne do zwracania z API. Map.of(k1,v1, k2,v2) max 10 par; więcej → Map.ofEntries().

Biznes: zwracaj immutable z serwisu — wywołujący nie psuje wewnętrznego stanu. Do budowania → ArrayList, na wyjściu → List.copyOf().

Część 8 — Typowe błędy

  1. LinkedList „bo wstawianie jest O(1)” — tylko na końcach; przy indeksie nadal O(n). W praktyce ArrayList wygrywa.
  2. Mutowalny obiekt jako klucz HashMap — po zmianie pola używanego w hash klucz jest nie do znalezienia.
  3. Brak equals/hashCode w encji jako kluczu — duplikaty w HashSet, „zgubione” wpisy w mapie.
  4. Modyfikacja kolekcji w enhanced for — ConcurrentModificationException; użyj Iterator.remove() lub stream z kolekcją mutowalną świadomie.
  5. subList() jako kopia — to widok na oryginał; zmiana subList zmienia parent.
  6. Arrays.asList() ma stały rozmiar — add/remove rzuca wyjątek; do mutowalnej listy: new ArrayList<>(Arrays.asList(...)).
  7. Sortowanie TreeSet bez spójnego Comparator — ClassCastException lub niespójność z equals.
  8. PriorityQueue.iterator() nie daje kolejności priorytetu — tylko poll()/peek() respektują heap.
  9. Domyślny rozmiar HashMap przy znanej liczbie elementów — zbędne rehash; ustaw load factor i initial capacity (expectedSize / 0.75 + 1).
  10. Vector / Hashtable w nowym kodzie — legacy synchronized; użyj ArrayList + ConcurrentHashMap.

Pytania rekrutacyjne — krótkie odpowiedzi

Junior / Mid

1. Jaka jest różnica między List a Set?

List — uporządkowana sekwencja, duplikaty dozwolone. Set — unikalne elementy, kolejność zależy od implementacji.

2. Czym różni się ArrayList od LinkedList?

ArrayList — dynamiczna tablica, szybki get(i) O(1). LinkedList — dwukierunkowa lista węzłów (prev/next), szybkie operacje na końcach O(1), wolny dostęp po indeksie O(n).

3. Jak wygląda węzeł w LinkedList?

Pola: prev (poprzedni węzeł), next (następny), item (dane). Lista jest dwukierunkowa.

4. Kiedy wybrać ArrayList?

Domyślnie zawsze, gdy potrzebujesz listy — częsty odczyt po indeksie, iteracja, dodawanie na końcu.

5. Jak działa HashMap?

Klucz → hash → indeks kubełka. W kubełku lista lub drzewo (przy wielu kolizjach). equals rozstrzyga kolizje.

6. Jaki jest kontrakt equals i hashCode?

Jeśli a.equals(b), to a.hashCode() == b.hashCode(). Spójność w czasie dla niemutowalnych kluczy.

7. Czym różni się HashMap od Hashtable?

HashMap — niesynchronizowany, null klucz/wartość dozwolone (1 klucz). Hashtable — legacy, synchronized, bez null.

8. Co to jest LinkedHashMap?

HashMap + lista dwukierunkowa utrzymująca kolejność wstawiania lub dostępu (access order).

9. Kiedy TreeMap zamiast HashMap?

Gdy potrzebujesz posortowanych kluczy lub operacji na zakresach (subMap, ceilingKey) — O(log n).

10. Jak zaimplementowany jest HashSet?

Jako HashMap — element to klucz, wartość to stały obiekt PRESENT.

11. Czym jest Deque?

Kolejka dwustronna — addFirst/addLast, pollFirst/pollLast. Implementacja: ArrayDeque.

12. Dlaczego nie używać Stack?

Legacy, extends Vector (synchronized). Zamiast tego ArrayDeque jako stos (push/pop).

13. Co robi PriorityQueue?

Kopiec — element o najwyższym priorytecie (min wg natural order/Comparator) dostępny przez peek/poll w O(log n).

14. Czy Map implementuje Collection?

Nie — osobna hierarchia. Mapa to pary klucz-wartość, nie kolekcja elementów.

15. Co zwraca List.of()?

Niemutowalną listę (Java 9+). Próba modyfikacji → UnsupportedOperationException.

Mid / Senior

16. Złożoność operacji na ArrayList?

get/set O(1), add(end) O(1) amortyzowane, add/remove(i) O(n), contains O(n).

Biznes: unikaj częstego wstawiania na początek dużej listy faktur.

17. Dlaczego LinkedList rzadko wygrywa z ArrayList?

Overhead węzłów, brak lokalności cache, O(n) dostęp po indeksie. CPU przewidywalnie szybszy na tablicy.

Wyjątek: Deque z częstymi operacjami na obu końcach — wtedy ArrayDeque, nie LinkedList.

18. Co się dzieje przy rehash w HashMap?

Nowa, większa tablica kubełków; elementy rozmieszczane ponownie wg hash. Koszt O(n), ale rzadki przy dobrym load factor (0,75).

19. Dlaczego Java 8 zmieniła kubełki na drzewo?

Ochrona przed atakiem kolizji hash — degradacja do O(n) na liście. Drzewo w kubełku → O(log n) przy wielu kolizjach.

20. Jak zbudować prosty LRU cache?

LinkedHashMap z accessOrder=true i removeEldestEntry() gdy size() > limit.

21. ConcurrentHashMap vs Collections.synchronizedMap?

CHM — lock na segment/ kubełek (lub CAS), lepsza skalowalność. SynchronizedMap — jeden lock na całą mapę.

22. Czy iteracja po ConcurrentHashMap jest snapshot?

Nie — weakly consistent: widzi elementy od startu iteracji, bez ConcurrentModificationException, może nie widzieć najnowszych zapisów.

23. computeIfAbsent vs ręczny get + put?

computeIfAbsent atomowe w CHM — jeden wątek tworzy wartość. Ręczny wzorzec może podwójnie utworzyć obiekt.

24. Kiedy CopyOnWriteArrayList?

Read-heavy, write-rare: lista listenerów, konfiguracja odczytywana przez wiele wątków, rzadko aktualizowana.

25. TreeSet a spójność z equals?

Jeśli compareTo zwraca 0, ale equals false — TreeSet uzna za duplikat. Comparator musi być spójny z equals.

26. Różnica Comparable vs Comparator?

Comparable — natural order w klasie (compareTo). Comparator — zewnętrzna logika sortowania, wiele strategii.

27. Co to jest fail-fast iterator?

Przy strukturalnej modyfikacji poza iteratorem → ConcurrentModificationException (modCount). Dotyczy ArrayList, HashMap.

28. subList(from, to) — pułapka?

Widok na oryginalną listę. clear() na subList usuwa zakres z parent. Zmiana rozmiaru parent może invalidować subList.

29. Initial capacity HashMap — jak liczyć?

ceil(expectedSize / loadFactor) + 1, domyślny load factor 0,75 — mniej rehash przy znanej liczbie wpisów.

30. Stream + modyfikacja źródłowej kolekcji?

Nie modyfikuj źródła w trakcie streamu na tej samej kolekcji — undefined behavior / CME na niektórych implementacjach.

Pułapki

31. Czy LinkedList ma szybkie wstawianie „w środku”?

Nie bezpośrednio — najpierw O(n) znalezienie indeksu, potem O(1) podłączenie węzła. Łącznie O(n).

32. Dwa obiekty z tym samym hashCode — czy są równe?

Nie muszą. equals rozstrzyga w kubełku. Kolizje hash są normalne.

33. Mutowalny klucz w HashMap — co się stanie?

Zmiana pola wpływającego na hash — wpis zostaje w złym kubełku. „Zgubiony” klucz, memory leak w mapie.

34. Arrays.asList(array) — czy mogę add?

Nie — fixed-size. set działa. Mutowalna kopia: new ArrayList<>(Arrays.asList(...)).

35. Czy PriorityQueue jest posortowana?

Nie w całości — tylko korzeń (min/max). Pełne sortowanie wymaga poll() w pętli lub stream().sorted().

36. Map.of() — null klucz lub wartość?

NullPointerException — immutable mapy z Map.of nie akceptują null.

37. Dlaczego nie używać enum jako klucza w TreeMap bez ostrożności?

Enum ma natural order — OK. Problem jest z klasami bez spójnego compareTo/Comparator, nie z enum.

Pułapka: custom Comparator na enumie ignorujący wartości — niespodziewane duplikaty w TreeSet.

38. keySet() vs entrySet() przy iteracji mapy?

entrySet() — efektywna iteracja par bez drugiego get(key). keySet() + get — podwójny lookup.

39. Czy size() ConcurrentHashMap jest dokładne w trakcie zapisów?

Przybliżone w starszych wersjach; w nowszych JDK liczenie może być kosztowne — nie polegaj na size w hot path bez dokumentacji wersji.

40. List<?> — czy mogę dodać element?

Nie — wildcard ? extends T uniemożliwia add (poza null). Kolekcja tylko do odczytu z perspektywy typów.
